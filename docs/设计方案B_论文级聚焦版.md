## 一、问题定义：场景的三个核心痛点

灾区"公网全瘫 + LEO 直连"场景下，标准 NTN 流程失效的根因可归结为三点：

| #  | 痛点                            | 机理                                            | 标准方案为何不够                                                       |
| -- | ----------------------------- | --------------------------------------------- | -------------------------------------------------------------- |
| P1 | **接入风暴**：公网瘫痪瞬间，海量终端冷启动并发接入   | 四步 RACH 轮次多、轮间 RTT 被 LEO 时延放大；RACH 碰撞风暴使成功率雪崩 | Rel-17 流程按常态负载设计，无突发冷启动机制；认证后置进一步拉长首连时延                        |
| P2 | **切换中断累积**：单星可见仅数分钟，通信全程需多次换星 | 常规切换"先断后建"，每次重走 RACH 与上下文重建，中断沿会话累积           | CHO/RACH-less 只前移了"准备与同步"，**认证状态跨星延续是空白**（灾区无核心网，标准上下文重建路径不可用） |
| P3 | **星上受限**：再生载荷算力/存储有限，不能堆重型机制  | 全量直接认证、区块链共识等均违背星上轻量化                         | 间接认证依赖地面（灾区失效），直接认证过重（P10 综述指出的两难）                             |

**核心洞察**：LEO 星座运动**确定可预测**——这是地面移动网没有的信息优势。把"预测"同时注入接入与切换，可以把大量本需在线交互完成的工作**前移为离线/提前计算**，从而绕开三个痛点。

## 二、系统模型与参数设定（与 A 版共用基线）

| 参数   | 设定                                                                    |
| ---- | --------------------------------------------------------------------- |
| 星座   | Walker δ 星座（默认 550 km / 53°，规模可配；对标 Starlink 一期公开参数），可选 TLE+SGP4 真实星历 |
| 覆盖   | 单星对地可见窗口约 5\~10 min；灾区任一位置在任意时刻至少有 1 颗可见星（星座规模下限由覆盖率仿真实验确定）           |
| 终端   | 静止/低速，GNSS 可用，**灾前预置设备根身份（出厂/eSIM，非卫星运营凭证；运营凭证由星上首联发证，见 Q4 双根模型）**                                    |
| 业务   | 三类：指挥话音 / 灾情图像 / 报平安短信                                                |
| 接入过程 | 冷启动批量到达（强度 λ 参数化扫描，覆盖"全城同时求救"量级）                                      |
| 星上约束 | 建模星上算力（比对操作/s 上限）与存储（上下文缓存条目上限）为仿真参数                                  |
| 威胁   | 伪造终端无合法凭证，试图占用接入资源（Dolev-Yao 模型）                                      |

## 三、机制一：轻量级两步接入协议（LAP, Lightweight Access Protocol）

**设计原则**：把"能预算的全部预算，能合并的消息全部合并"。

```HXML
终端                          卫星
  │  ① 离线预计算：星历(SIB19)+GNSS → TA/多普勒预补偿
  │ ────── MsgA ────────────────────→ │
  │   [前导 | TID | Token_t | Type]   │ ② 本地一次比对：
  │   字段定长定址，布局固定           │    Token_t ?= H(cred, t, SAT_ID)
  │ ←───── MsgB ────────────────────  │    比对通过 → 指配资源+精确TA
  │   [确认 | 资源指配 | TA校正]       │    不通过 → 静默丢弃（不耗信令）
```

- **两条消息完成"同步 + 接入 + 认证"**（基线：四条接入消息 + 后置认证交互）。
- **认证强度分级（方向 C，2026-09-01 确认）**：终端**首次冷启动接入**采用**无证书公钥（CLC / CL-PKC）强认证**（一次性）——终端先证明**设备根身份（出厂/eSIM 预置）**，星作为在轨 KGC 下发 CL-PKC 部分私钥 + 假名（双根模型见技术决策确认 Q4）；已完成首认的终端在**后续每次切换采用哈希链续认证**（星上一次比对），续认证上下文由星历预测驱动提前准备。两条路径共用下方定长定址字段布局，切换重连复用同一套比对逻辑。
- **轻量性**：星上仅一次哈希比对（O(1)），无公钥运算、无状态机长会话；令牌一次性（时间窗 t + 卫星 ID 绑定），抗重放。
- **拥塞控制**：卫星按 RACH 实测负载广播三档负载等级；终端按"业务优先级 × 负载等级"查表确定退避窗口——高负载下低优先级业务自动退避让路，无需集中调度。
- **为什么这就算"轻量级协议"**：协议状态数最小（终端 2 态、卫星无 per-UE 状态直至比对通过），信令字段定长定址（同时服务 M2 的一次比对），实现复杂度集中在可离线验证的预计算环节。

## 四、机制二：星座预测预拓扑驱动的无缝切换（PTHO, Pre-Topology HandOver）

**核心思想**：星座运行是确定的 → 把"未来一段时间内每个区域依次由哪些星覆盖"**离线预计算成一张时间展开拓扑（Contact Plan / 预拓扑表）**，切换从"在线发现"变为"查表执行"。

### 4.1 预拓扑层（离线，地面侧或灾前预置）

- 输入：星座星历、灾区地理网格、业务时延约束；
- 输出：**区域—时间—卫星序列表**（每个网格每时段的主服务星 + 后继星 + 预测切换时刻窗）；
- 性质：表项在星历更新周期内有效；终端与服务星**共用同一张表**，天然实现 Text.txt ④要求的"双端同步锁定"，无需在线协商切换目标。

### 4.2 在线执行层（三动作）

1. **预迁移（先建后断）**：当前星按预拓扑表，在预测切换窗之前将终端最小上下文 {TID, Token 摘要， 上下文序号 SN} 打包为**终端携带的安全上下文令牌**（百字节级）；v1 不建模星间链路，由终端在切换重连时呈交后继星（ISL 推送为未来增强，2026-09-01 决策）。确认 / 超时后原星释放。
2. **一次比对重连**：终端进入后继星波束，发送定长重连帧 \[TID | Token 摘要 | SN]；后继星与预迁移缓存**一次比对**即恢复通信，跳过完整接入（切换期的"快接"复用 LAP 的字段布局与比对逻辑——一套协议管两件事）。
3. **双条件判决 + 回退**：预拓扑给出"默认切换时刻"，但是否执行仍过双条件闸门——剩余可见时间满足业务约束 **且** 链路稳定 → 按表不切换（防乒乓）；任一不满足 → 提前切换。实际可见星 ≠ 表定后继星（失配）→ 回退 LAP 两步接入，**失配只降级不失效**。

### 4.3 为什么"预拓扑"优于在线预测

| 对比维度  | 在线逐次预测（CHO 类）  | 预拓扑表（本方案）          |
| ----- | -------------- | ------------------ |
| 双端一致性 | 需信令协商/配置，存在失配面 | 共用同一张表，天然一致        |
| 星上计算  | 每切换周期在线计算      | 查表 O(1)，零在线轨道计算    |
| 信令开销  | 每终端每切换需配置消息    | 表随星历周期统一下发，摊薄      |
| 失配处理  | 触发即执行，失败重选     | 判决闸门 + 回退 LAP，路径明确 |

## 五、复杂度与开销分析（轻量化论证）

| 资源       | 开销                        | 说明                                      |
| -------- | ------------------------- | --------------------------------------- |
| 星上计算（接入） | 1 次哈希比对/终端                | 对比 5G-AKA 的多次向量运算与核心网交互                 |
| 星上计算（切换） | 查表 1 次 + 比对 1 次/终端        | 无在线轨道计算、无协议状态机重建                        |
| 星上存储     | 每终端 ≤ 百字节 × 在窗终端数         | 上下文确认后释放；存储上界 = 单星覆盖区内终端数 × 记录大小，可参数化压测 |
| 终端携带令牌（v1 不建模 ISL） | 安全上下文随终端重连帧呈交，零星间链路开销；ISL 推送为未来增强 | 相比切换信令全量重建可忽略；契合灾后信关全瘫场景 |
| 终端       | 预补偿计算（Rel-17 已强制具备）+ 令牌哈希 | 无新增硬件假设                                 |

## 六、评估设计（论文实验框架）

**对照组**：① 3GPP Rel-17 四步 RACH + 常规硬切换（基线）；② 2-step RACH（SOTA 接入）；③ CHO + RACH-less（SOTA 切换）。

**指标**：平均/95 分位接入时延、接入成功率—负载曲线、切换中断时间、切换成功率、乒乓率、预测失配率—性能退化曲线、伪造终端拦截率、星上开销实测（比对时延/缓存峰值）。

**关键实验**：

- E1 接入风暴扫描：λ 从常态到"全城求救"量级，验证 LAP 成功率曲线不衰减拐点更靠右（目标：成功率 +20%、时延 −30%）；
- E2 长会话多切换：统计中断时间累积分布（目标：中断 −40%）；
- E3 失配率注入：人为扰动预拓扑表，刻画失配率—性能曲线，给出机制适用边界（论文"诚实性"实验）；
- E4 消融实验：预补偿 / 预迁移 / 双条件判决分别开关，量化各组件贡献（论文必备）。
