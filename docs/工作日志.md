## 2026-09-01 双轨时延口径统一与全量复跑验收

### 背景
Python 协议参考模型（[sim/protocol.py](sim/protocol.py)）与 ns-3 离散事件模型（[.ns3_ref/leo_access.cc](.ns3_ref/leo_access.cc)）此前在接入时延口径、成功率统计、拥塞统计三处不一致，导致两轨数值不可比。

### 本次修复（6 项，全部落地）
1. Python 轨接入阶段重构为时间有序离散事件队列（小顶堆按时刻弹出接入尝试/碰撞退避/可见性等待），与 ns-3 Simulator 调度同序，消除「按终端序号处理」造成的拥塞统计偏差。
2. 双轨接入时延统一为端到端口径：Python 轨 `value_ms = (GRANT 完成时刻 − 首次发起时刻)×1000`，ns-3 轨 `delay_ms = (t − m_burstT)×1000`，均含退避/等待与握手全程。
3. 成功率口径修正：接入成功率仅统计合法终端；伪造终端由「伪造终端数/拦截率」单独汇报（T4 口径），两轨同名同口径（`eval.compute_metrics` 与 `ns3_io.compute_ns3_metrics`）。
4. trace 契约扩为 14 列（新增 `ho_el_cost_deg`、`forged`），[docs/仿真接口约定.md](docs/仿真接口约定.md) 同步并明确建模边界（T4 认证、RACH 基线、碰撞拥塞均为高层建模）。
5. 场景集扩展：新增 wenchuan_storm2（两步接入·呼叫风暴）与 wenchuan_storm4（Rel-17 四步 RACH 基线）对照场景。
6. 清理临时取证脚本（probe_chain.py / probe_mismatch.py），删除已转 Markdown 的两份 docx 计划书。

### 验证结果（8 次运行，4 场景 × 双轨，全部通过）
- 常规场景（汶川/河南）双轨完全同构：接入成功率均 1.0000；接入时延 13.14 vs 13.15 ms（汶川）、12.39 vs 12.37 ms（河南）；切换中断双轨均 0；乒乓率均 0；伪造拦截率均 100%。
- 风暴场景（storm2）统计性差异：Python 0.6454 vs ns-3 0.8194。成因明确——双轨独立 RNG（Python random vs ns-3 RngStream）在饱和退避-碰撞非线性过程下被放大，非口径或逻辑差异（默认场景逐位一致为证）。
- 两步 vs 四步 RACH 基线：双轨相对行为完全一致（成功率不变、时延精确 +400 ms），协议级增益可量化。
- 交付物：docs/双轨交叉验证对照表.md（完整 14 指标对照 + 差异分析 + 检查清单）。
