| `value_ms` | float | ACCESS 为接入时延(ms)；HANDOVER 为切换中断(ms) |
| `doppler_hz` | float | 事件时刻多普勒(Hz，可负) |
| `slant_km` | float | 事件时刻斜距(km) |

| `pingpong` | bool | 乒乓切换标记（0/1） |
| `ho_el_cost_deg` | float | 仰角代价（°）：执行时刻仰角最优星瞬时仰角 − 选中星瞬时仰角（仅 HANDOVER 有效） |

| `service` | enum | 业务类型：`voice` / `image` / `sms`（★2026-09-23 新增★，与 `config.SERVICE_TYPES` 同分布 0.2 / 0.5 / 0.3；HANDOVER 与 ACCESS 均写） |

### 2.1 指标口径（与报告一致）

- **接入成功率** = 合法终端成功接入数 / 合法终端接入事件数（伪造终端不计入分母，其拦截情况由「伪造终端数 / 伪造终端拦截率」单独汇报）。
- **接入时延** = (GRANT 完成时刻 − 终端首次发起时刻)×1000（ms），**端到端**口径：含碰撞退避/可见性等待与两步（或四步）握手全程；**仅统计成功接入的合法终端**（`value_ms > 0`，失败事件记 −1 不入均）。常态无拥塞时退避项≈0，时延≈2×传播时延+星上处理+认证/四步附加。
  > ⚠️ **口径使用注意（2026-09-16 补）**：因只统计成功终端，**跨方案比较时存在幸存者偏差**——成功率差异大时（如窄带场景 0.72 / 0.41 / 0.16），低成功率方案的均值只覆盖少数"快速成功"终端，会显得时延偏低。故**跨方案比较必须并读 `接入成功率` 与 `RACH吞吐_终端每秒`**（二者无该偏差）；本约束在 T3 接入方案对比中已显式适用于两轨。
- **伪造终端数 / 伪造终端拦截率** = 伪造终端接入事件数 / 其中被星上凭证校验拒绝（result=fail）的占比。
- **切换中断** = `max(0, 新链可用 − 旧链真实丢失)`，其中新链可用 = 目标可达时刻（重叠候选为决策时刻 t_ho，盲区兜底为目标 AOS）+ 重连确认时长（2×传播+星上处理+认证）。预测式重叠切换在决策时刻即刻建链（先建后断），`ho_lead_s` 提前量直接压缩中断。
- **乒乓切换率** = 满足以下任一判据的 `HANDOVER` 占比：a) 窗口内切回曾服务过的星且间隔 ≤ 60s；b) 相邻两次切换间隔 < 30s。
  > ★**构成分解（2026-09-16 新增，三指标并列汇报）**★：原合并判据掩盖了两种性质不同的现象，现由 `sim/eval.py` 同时输出：
  > - `乒乓_切回率` = 仅判据 a（窗口内切回曾服务过的星）—— **T6「抑制乒乓」真正要抑制的对象**（真·抖动）；
  > - `乒乓_快速连切率` = 仅判据 b（相邻切换 < `PINGPONG_MIN_GAP_S`）—— 可能来自**提前切换策略保零中断的接力代价**；
  > - `乒乓切换率` = a ∪ b（保留原口径，向后兼容）。
  > 使用建议：不要把 `乒乓切换率` 单独当作缺陷指控，**须与 `切换中断均值` 并读**（例：预测式 `predictive` 乒乓 0.041 全为快速连切、切回 0.033，是其"多切一次换零中断"的显式代价；反应式 `rel17` 乒乓为 0 是因其不提前切换，代价是中断 380.5 ms）。
- **预测失配率** = 在旧服务星丢失时刻，决策选中的目标星不再是仰角最优可见星的 `HANDOVER` 占比；衡量基于星历预测的窗口尺度最优性。高密度 LEO 星座下贪婪策略此值偏高，改进方向为更长提前量 / 迟滞 / 仰角-窗口联合优化。
- **仰角代价（均值/最大）** = `ho_el_cost_deg` 的统计量（°）；量化“稳定优先（驻留最长）”相对“仰角最优”的实质牺牲，诚实汇报。

## 5. 数据源溯源与建模边界（审计用）

- **真实数据**：星座 TLE 来自 Celestrak（`provenance.url`），抓取时间入档；可见窗 / 多普勒 / 时延为 `TLE + skyfield` 真实计算，无硬编码。
- **建模边界（诚实声明）**：
  1. 终端数、突发强度、危险度分布：`scenario.py` 设定（仿真输入，非外场实测）。
  2. 本 ns-3-dev **未安装 `satellite` / `nr` 模块**，链路层为**自定义 LEO 信道**（应用层承载 `ns3::Packet` 并按传播时延调度投递），非 3GPP NTN 物理层。
  3. T4 认证为**真实 HMAC-SHA256 凭证**（根密钥派生设备密钥、假名标识、计数器防重放），双轨同构；星上校验附加时延 `auth_extra_ms` 由本机实测校验耗时×星上降频系数折算。伪造终端分两类：盲伪造（无有效密钥，HMAC 校验失败即拦截）与密钥泄露型（持有效密钥，密码层不可检出 → 漏检，由 `compromised_share` 控制占比）；碰撞/拥塞模型为**星上按 10ms 时间片限流**（`rach_capacity` 前导码受理上限、生存优先三池预留）+ 终端均匀随机退避重试（`retry_interval_ms`/`retry_max`）。
  4. 两步/四步 RACH 差异为**机理建模**：四步含前导竞争（同星同时隙同前导冲突 → 退避）+ RAR 响应窗口（`rar_window_ms`）+ 竞争解决定时器（`cont_timer_ms`）+ 额外几何往返，均实算而非固定附加时延。
  5. 仿真值为既定场景假设下的结果，**非外场实测**。
  6. **T2 切换基线矩阵的忠实度（2026-09-16 补）**：`dqn` 为 **DQN 收敛策略的确定性等价**（非在线神经网络训练，亦非论文原方法的 MADQN 集中训练/多智能体）；`graph` 在本模型**无卫星容量约束**下，Kuhn-Munkres 最大权匹配数学上退化为**加权 argmax**（其负载惩罚项为弱归一、不 binding）。二者定位为**近似实现**，仅作**机制对照**，不与原论文做绝对数值比较。
  7. **T3 接入方案的资源记账（2026-09-16 补）**：时隙准入按方案扣减容量单位 `RACH_SLOT_UNITS`（`twostep_precomp`=1 / `rel17_4step`=2 / `msgarep_2step`=M=4）；若不作此区分，成功率只由容量上限决定、与接入方案无关。另：`msgarep_2step` 的 M 份副本按**各占独立前导资源**建模（忠实资源外部性），故其分集增益在窄带/高冲突场景下可能被资源代价抵消——结论已如实记录。
  8. **跨轨 T8 业务连续性（★2026-09-23 已补齐★）**：契约自 2026-09-23 起为 **17 列**，新增 `service`（业务类型）。
     - ns-3 侧 `LeoApp::m_service` 由 `SetService()` 按 voice 0.2 / image 0.5 / sms 0.3 抽样（镜像 `config.SERVICE_TYPES`），
       并已**写入 trace 的 `service` 列**；`eval.service_continuity_metrics` 据此**按业务拆分**话音/图像/短信 → **T8 双轨可比**。
     - 历史（16 列时代）：ns-3 写 trace 时业务类型丢失、`eval` 按 `sms` 回落 → ns-3 轨只产出「短信业务」键，
       T8 业务区分只能以 Python 轨为准。**该限制已随契约扩列消除**，两轨 T8 现均可按业务比较。
- **绝不**：把仿真值伪装为实测值；无源数据直接拒收。

python exp/t3_access/run_t3.py        # → exp/t3_access/t3_table.txt（3 场景 × 3 方案）

# 仅生成输入 / 仅统计（调试用）
python -m sim.ns3_io
