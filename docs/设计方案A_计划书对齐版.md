## 三、总体架构（对齐计划书模块二）

天基—空基—地面三层融合（空基为弹性扩展层，工作量边界受控）：

```
天基段（LEO 星座）：星地链路 / 星间链路 / 回传链路三链路协同
  承担：广域覆盖、星上本地认证、切换判决与分级接入调度
空基段（无人机/飞艇，可裁剪扩展层）：
  承担：就近汇聚接入请求（卸载卫星侧 RACH 负载）、局部补盲、协同认证转发
  边界：不做编队控制与轨迹规划，仅建模为可配置汇聚节点（数量/半径/驻留时长）
地面段（灾后残存网络）：
  承担：存活基站/自组网终端作为汇聚中继，聚合周边请求统一接入
```

## 四、核心机制设计（对齐计划书模块三、四）

### M1 安全快速接入握手（模块三，四个优化方向）

1. **减少握手轮次**：星历 + GNSS 开环预补偿（TA/多普勒），四步接入压缩为两步（MsgA 内嵌认证令牌与业务标签，MsgB 完成确认与指配）——**接入与认证同步完成**。
2. **生存优先分级接入**：综合优先级 = f（业务优先级， 终端位置危险度），高优先级终端使用专用前导码分组，实现"最危险的人先接入"（创新点·温度）。
3. **拥塞控制**：接入强度感知退避（卫星广播负载等级）+ 地面/空基汇聚中继的请求合并，抑制接入风暴。
4. **无核心网轻量认证**：预共享凭证 + 一次性令牌，星上本地比对验证；借鉴跨域认证思想引入动态匿名标识（轮换、与长期身份解耦），物理层指纹不作为仿真实现（仅威胁分析论证）；**不引入区块链共识**（创新点·安全）。

### M2 预测式无缝切换（模块四，五项机制）

1. **切换预测与目标锁定**：星历 + 终端位置预测下一可见卫星，双端（终端/网络）同一算法同一星历版本保持同步，避免预测失配。
2. **认证上下文预迁移（先建后断）**：当前卫星将认证状态、上下文序号、凭证摘要经星间链路提前打包迁移至目标卫星。
3. **信令格式规范化 + 一次比对重连**：关键字段（标识/凭证摘要/序号）位置与内容固定，新卫星一次比对即确认，跳过完整接入认证。
4. **双条件切换判决**：剩余可见时间满足业务时延约束 **且** 链路质量（SNR/丢包趋势）稳定 → 不切换；任一不满足 → 触发预备切换（抑制乒乓）。
5. **业务感知平滑切换**：话音保中断最小、图像断点续传、短信可排队。

**失配回退**：预测失配时回退 M1 两步接入；失配率作为独立实验变量。

## 五、仿真平台与演示（对齐计划书模块五）

- **双轨架构**：ns-3 协议级仿真（接入/切换/认证的严谨性能评估）+ Python 数字孪生推演（轨道模型、灾害场景参数化、可视化）。
- **分层递进实验**：E1 单终端验证机制正确性 → E2 多终端验证分级调度与拥塞控制 → E3 攻击仿真（伪造终端拦截）与失配压测。
- **空基增益专项实验**：仅卫星 / 卫星+地面汇聚 / 卫星+地面汇聚+空基 三配置对比（创新点·演示的支撑实验）。
- **历史灾害复盘**：内置汶川、河南暴雨场景参数包，推演"若当时部署本方案"的对比复盘。

## 六、限制需求符合性对照

| # | 限制条件 | A 版符合性说明 |
|---|----------|----------------|
| 1 | 星上资源有限 | 认证为本地比对（无公钥运算、无共识）；预迁移上下文限定百字节级最小集；仿真建模星上算力/存储参数并考核 |
| 2 | 不做数据预处理 | 星上仅缓存/比对/转发；全部机制在协议信令层 |
| 3 | 仅仿真验证 | 双轨仿真；指标均为相对基线百分比 |
| 4 | 灾区无核心网 | 认证、切换判决全部星上本地完成；回传缺失场景经星间链路路由至远处信关站做可行性分析 |
| 5 | 基线 = Rel-17 NTN | 对照组严格复现四步接入 + 常规切换；Rel-18 仅作演进参考 |
| 6 | 轨道模型从简 | Walker 简化模型为主、TLE 可选；不陷入轨道力学细节 |
| 7 | 认证不增加握手轮次 | 令牌内嵌 MsgA 既有载荷；切换重连为单消息一次比对 |
| 8 | 空基工作量边界 | 不做编队/轨迹规划；仅可配置汇聚节点；进度紧张可整体裁剪不影响主线交付 |
| 9 | 本科团队一年周期 | 分层递进实验；四方向独立出结果，保证至少两方向出效果 |
| 10 | 与现有技术不重复 | 认证上下文星间预迁移 + 一次比对确认在标准与文献中无先例（见《现有技术分析综述》§五） |

## 七、与 B 版的关系

A 版 = **做全**：对齐计划书全部承诺（四维创新、五大模块、三层架构），是立项与结题的对账依据。
B 版 = **做深**：抽取 A 版中技术含量最集中的内核（轻量接入协议 + 星座预拓扑预测切换），按论文标准打磨成可发表的核心贡献。
执行顺序建议：B 版先行（本学期机制突破 + 数据产出），A 版扩展项（空基增益、复盘场景包）后补。
