> 审计对象：面向应急救灾的低轨卫星-地面融合组网快速接入系统（仿真工程 `sim/` + ns-3 轨 `.ns3_ref/leo_access.cc`）
> 审计日期：2026-09-02 ｜ 方法：全量代码逐行审查 + 独立脚本复算 trace + 对照实验重跑 + 版本控制核查

>
> **总体结论**：轨道/几何/多普勒/可见窗这一层**真实可信**（真实 TLE + skyfield，可复现）；

### 1.3 写死返回值 / 结构性恒等（★核心发现★）

**① 切换中断：Python 轨直接写死 `0.0`**

```python
# sim/protocol.py:247-258
if overlap:
    best = max(overlap, key=lambda w: w["los_s"])
    start_connect = los_t
    interrupt = 0.0          # ← 写死，非计算结果
    pingpong = 1 if (best["los_s"] - t_ho) < 60.0 else 0
elif nxt is not None:
    ...
    interrupt = max(nxt["aos_s"] - los_t, 0)
```

实测 9024 条切换事件中该分支命中率 100%（OneWeb 651 星恒有重叠），故中断恒为 0。

ns-3 轨虽为计算式（`leo_access.cc:405-407`），但同样是恒等式：

```
confirmT = t + 2·delay + proc ≈ (los − 20s) + 11 ms
interrupt = max(0, max(los, confirmT) − los) = max(0, confirmT − los) ≡ 0
```

**只要 `ho_lead > 2×传播时延 + 处理时延 ≈ 11 ms`，中断必然为 0。**
取 `ho_lead = 20 s` 时余量达 19.99 s——任何预测方案、甚至一个完全不预测的方案，
只要提前 12 ms 发起都能得到"0 ms 中断"。
**"预测式切换实现 0 ms 中断"不是本算法的贡献，是参数选择的算术后果。**
实证：`run_sim.py` 全部 4 场景 × 双轨 = 8 组，中断非零事件数 **0**。

**② 乒乓切换率：由选优规则保证恒为 0**

选优取 `argmax(los)`（`protocol.py:249` / `leo_access.cc:346`），
判据为 `(candLos − tHo) < 60`（`protocol.py:252` / `leo_access.cc:403`）。
被选中的必然是 los 最大者，因此判据为真 ⟺ **所有候选剩余可见都 < 60 s**。
在 651 星、单星过境约 400 s 的星座下这几乎不可能发生 → 实测 **0/9024 与 0/9216**。

该指标对任何"驻留优先"策略恒为 0，**不可证伪**。
且真实的乒乓（切回上一服务星、短时间内连续切换）完全未被建模。
`docs/双轨交叉验证对照表.md:81` 已自述成因（"候选必须…剩余可连 >60 s 才入选"），
但仍将其列为"验证通过项"。

**③ 伪造终端拦截：终端自报比特，卫星照单执行**

```cpp
// .ns3_ref/leo_access.cc:731  终端侧：自己抽签决定自己是不是伪造
app->SetForged(g_forgedRatio > 0 && u(rng) < g_forgedRatio);

// .ns3_ref/leo_access.cc:456  星侧：读该比特直接拒绝
if (h.forged){ g_dbg_forged_blocked++; ... deny ...; return; }
```

```python
# sim/protocol.py:179-184
is_forged = random.random() < forged_ratio
if is_forged:
    n_forged += 1
    n_forged_blocked += 1          # 无任何判定分支，必然 +1
    trace.append(_mk_access(..., "fail", forged=True))
```

**全项目 grep `hmac|sha|signature|schnorr|ecc|nonce|challenge|cert` → 零命中。**
`docs/T4协议伪代码草图.md` 设计了完整的 EC-Schnorr / CL-PKC / 哈希链 / 假名轮换，
但 `LeoHeader`（`leo_access.cc:148-183`）中**没有任何 `dev_sig`/`nonce`/`tid`/`hash_seed` 字段**。
代码注释反复写"dev_sig 校验失败"，而 `dev_sig` 在实现中不存在。

> 拦截率 100% 是**同义反复**："被标记为伪造的终端都被判定为伪造"。
> 既无漏检率（伪造终端骗过校验）也无虚警率（合法终端被误拒），因为判定不依赖任何凭证计算。

### 1.6 对照实验的有效性

重跑风暴对照（`--no-viz`，种子 20260901）：

| 场景 | 成功率 | 时延均值 | 时延 P95 |
|---|---|---|---|
| storm2（两步） | 0.6454 | 356.0 ms | 1012.75 ms |
| storm4（四步） | **0.6454** | 756.0 ms | 1412.75 ms |
| 差值 | **0** | **+400.00 ms** | **+400.00 ms** |

差值与 `step4_extra_ms = 400.0` **完全相等，精确到小数点后两位**。
`docs/双轨交叉验证对照表.md:67-68` 亦自认"成功率差异 0"。

**问题**：真实系统中四步 RACH 会改变碰撞动力学（msg3 重传占用更多时隙、竞争解决失败需重走全流程），
成功率**必然**低于两步。此处两步与四步共用完全相同的碰撞模型，仅末端加常量，
因此"对比"退化为"把输入假设重新输出一遍"。
答辩追问"为什么四步成功率与两步完全相同"时，无法回答——因为这**不是仿真得出的结论**。

相对地，风暴场景的**碰撞退避机理本身是真实计算的**（容量 4/10 ms × 100 时隙 = 400 个/s，
1200 终端需 3 s 消化，部分终端 `retry_max=3` 超限判失败）→ 这部分可信。

### 3.4 错误处理缺失

| 位置 | 问题 | 后果 |
|---|---|---|
| `protocol.py:80-81` | `except: return (0,0,0)` | 几何失败 → 斜距 0 km 静默写进 trace，指标被污染且无痕迹 |
| `protocol.py:106-107` | `except: v = 0.0` | 仰角失败 → 0°，导致选星错误，且被当作合法低仰角 |
| `orbit.py:54-60` | 静默 `continue` | 坏 TLE 无声丢弃，provenance 卫星数失真 |
| `run_ns3.py:81-82` | 吞异常 + 用旧 trace | **陈旧数据冒充新结果**（§1.5） |

### 3.5 可维护性风险

1. **中文键名作为程序接口**：`metrics` 用 `"接入成功率"` 等中文作 dict key 并直接 `json.dump`。
   无法被标准 JSON Schema / 类型检查 / 前端 i18n 工具链消费，且 `Agents.md` 一·B 规划的 "Python → Web" 接口尚无消费者。
2. **产物无命名隔离**（§1.5 已实证造成报告/数据错配）。
3. **双轨一致性靠注释维系**：`# 与 ns-3 轨同名同口径` 出现 6 次，无契约测试。
   `docs/仿真接口约定.md` 定义了字段，但**没有自动化测试校验两侧字段名与口径**。
4. **`docs/双轨交叉验证对照表.md` 为手抄数据**：表中 24 行指标无生成脚本，改代码后需人工同步，必然漂移。
5. **ns-3 随机种子固定**（`leo_access.cc:731`）：`run_sim.py` 支持 `--reps 5` 出置信区间，
   `run_ns3.py` **完全不支持任何种子参数** → ns-3 轨无法做统计显著性检验。

## 五、分阶段优化方案

### 阶段一：止血（P0，建议 1 周内，答辩材料定稿前）

| 序 | 动作 | 预期收益 | 验证方式 |
|---|---|---|---|
| 1 | T4 实现 HMAC-SHA256 轻量凭证：终端携带 `(pseudo_id, counter, MAC)`，星上验签；伪造终端携带错误 MAC。同步输出**漏检率**与**虚警率** | 拦截率从"同义反复"变为**有判别力的指标**；`auth_extra_ms` 由常量变为可调参数 | 构造 3 组实验：`forged_ratio ∈ {0, 0.05, 0.2}`，验证拦截率 ≈ 100% 且**虚警率 ≈ 0**；再注入"MAC 位翻转"验证漏检率 < 某阈值 |
| 2 | 若 1 来不及：**立即从所有报告/答辩材料删除"伪造终端拦截率 100%"结论**，改为"T4 认证机理实现中，当前为占位" | 规避最严重的失守点 | 人工核查文档 |
| 3 | 切换中断去恒等：加入**切换执行开销**（PREP→CONFIRM 信令、目标星未响应重选），并做 `ho_lead ∈ {0.5, 1, 5, 10, 20, 60} s` **敏感性扫描** | 产出"中断 vs 提前量"曲线，证明 0 ms 中断所需的最小提前量——**这才是有价值的结论** | 扫描曲线必须在小 `ho_lead` 处出现非零区；若仍全 0 说明建模仍不足 |

## 六、审计结论一句话

> **真实的部分很真实**（TLE 星历、轨道几何、多普勒、可见窗、碰撞退避动力学、ns-3 离散事件调度——均已独立复算确认）；
> **但三个核心指标（切换中断、乒乓率、伪造拦截率）当前不可证伪，两步 vs 四步的核心对比由无源常量定义，
> T4 认证、T7 重连确认、T8 业务连续性、L2 信道层尚未实现。**
> 优先级：**先修指标的"可证伪性"与 T4 的"去 Mock"（阶段一），再谈算法调优（阶段二）**——
> 因为当前的"完美结果"（100% 成功、0 ms 中断、0 乒乓、100% 拦截）恰恰是最脆弱的部分：
> 它们全部由构造保证，而非由算法赢得。
