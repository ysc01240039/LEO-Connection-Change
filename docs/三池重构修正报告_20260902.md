# 生存优先 RACH「三池」重构修正报告（2026-09-02）

> 承接 `docs/生存优先调度与双轨一致性验证_20260902.md`。上轮发现 2 池模型下 **med<low 成功率排序异常**（报告第五节点 3「已知建模简化」）。经代码核对确认根因，用户确认改为三池，本文档记录改动、验证结果与双轨对照。

## 一、根因（代码级）

旧 `_slot_ok`（`sim/protocol.py` / `leo_access.cc slotOk`）为 **2 池**：high 占专用预留池（`PRIORITY_RESERVE_FRAC=0.5`），**med/low 共用同一共享池**。

- high 专用池满后**溢出进共享池**，与 med/low 争夺同一共享容量；
- 退避系数 `PRIO_BACKOFF={high:0.3, med:0.6, low:1.0}` 方向正确（低优退避更大、重试更慢）；
- 拥塞下**退避快反而吃亏**：med(0.6) 反复撞满的共享池空耗时隙，low(1.0) 最慢、反而"熬"过风暴窗口才成功 → low 成功率高于 med。

即 med<low 是**共享池耦合 + 退避×拥塞动力学**的产物，非退避写反（退避方向本就正确）。

## 二、修复方案：严格三池、互不借用

改用 **high / med / low 各占专用预留池**，比例 `PRIORITY_RESERVE_FRAC = {0:0.5, 1:0.3, 2:0.2}`：

- 每档独占自身容量，顺序 `cap[0]≥cap[1]≥cap[2]` 由容量直接保证 **high>med>low 单调**；
- 容量余数归 low（`cap[2] = rach_capacity − cap[0] − cap[1]`），**总容量恒 = rach_capacity**，不丢吞吐、不与 2 池总吞吐发生变化；
- **刻意关闭"向低优档借用"**：若允许 high 溢出吃 med/low 池，high 会先吃 med 池再吃 low 池 → 重演 med<low，故严格隔离。

改动文件：
| 文件 | 改动 |
|---|---|
| `sim/config.py` | `PRIORITY_RESERVE_FRAC` 标量 0.5 → 三档字典 `{0:0.5,1:0.3,2:0.2}` |
| `sim/protocol.py` | `_slot_ok` 改三路专用池 `_load_p[3]`，先占本档、不借用 |
| `.ns3_ref/leo_access.cc` | `g_priorityReserveFrac` 改数组 `[3]`；`g_slotRes/g_slotSh` → `g_slotP[3]`；`slotOk` 严格三池；新增 `--prioResHigh/Med/Low` |
| `run_ns3.py` | 透传三比例（与 config 同源） |

## 三、验证结果（wenchuan_storm2 · 呼叫风暴 · 优先级开启）

| tier | Python 成功率 / 时延(ms) | ns-3 成功率 / 时延(ms) |
|---|---|---|
| **high** | 0.8853 / 46.05 | 0.984 / 38.28 |
| **med**  | **0.3929** / 214.82 | **0.6605** / 166.84 |
| **low**  | **0.3043** / 437.14 | **0.5307** / 436.08 |

→ **high > med > low 在成功率与接入时延上均单调成立**，双轨一致。**med<low 假象已消除。**

优先级增益保留：
- Python：成功率差(high−low)=**0.581**，时延降低%=**89.5%**
- ns-3：成功率差=**0.4533**，时延降低%=**91.2%**

（拒绝数同样单调：Python high25/med255/low368；ns-3 high4/med129/low237。）

## 五、客观说明（不回避）

1. **两轨绝对数值仍不同**（storm2 high 0.8853 vs 0.984）：独立 RNG 流 + 事件调度器（heapq vs ns-3 Simulator），设计内「交叉验证」非逐位复现；相对排序与优先级增益方向一致。
2. **切换中断量级差（Python 1862 vs ns-3 536）**：两轮报告已说明——两轨均为预测式触发（`t_ho=预测LOS−ho_lead`）、均相对真实 LOS 量中断，差异来自残馀建模细节（触发用预测/真实 LOS 计算、误差注入分布、决策/执行候选重选口径）。**两轨同为"预测式、相对真实 LOS 算中断"，ns-3 不更"科学"，只是预测/真实 LOS 拆得更显式。** 如需逐位对齐，应统一两轨同一套显式定义（非本轮回填范围）。
3. **med<low 已修复**，但若某场景 med 终端数显著多于 low，strict 三池下 med 仍可能因自身需求过大而成功率偏低——属场景需求属性，非建模缺陷。

## 六、结论

生存优先分级调度 now 满足计划书「温度」创新点的完整语义：**high 绝对优先（独占最大专用池 + 最快退避）、med/low 严格保底且 high>med>low 单调**，双轨交叉验证一致，Rel-17 基线对照无回归。可答辩。
