## 〇、一句话锁定

- **接入侧（T3）**：突发风暴优先级保障 = 高优先级前导码分组 + 调度优先服务（混合式）。
- **安全侧（T4）**：认证机制 = **方向 C 混合**——初始接入用无证书公钥（CLC / CL-PKC）强认证（一次性，双根预置 + 星侧受灾判定，见 Q4）+ 后续切换用哈希链轻量续认证；续认证上下文由星历预测驱动提前准备；动态匿名标识（假名）轮换。具体算法（2026-09-01 决议）：**EC-Schnorr CL-PKC**（星=在轨 KGC、主私钥不传星）；假名**每次切换轮换**；哈希链**首联 MsgB 下发种子 + 索引单向递增**；令牌**复用星座根 kid 签名**（任意目标星直验）。
- **切换侧（T5~T8）**：认证上下文预迁移通路 = **终端携带令牌（terminal-carried token）**；v1 不建模星间链路（ISL）、不依赖灾后已瘫的信关站。

## 一、三招已确认决策

### 1. 接入侧 T3 — 突发风暴优先级保障
- **机制**：高优先级前导码分组 + 调度优先服务（混合式，非纯排序、非纯预留）。
- 优先级 = f(业务优先级, 终端位置危险度)；业务三档：指挥话音 > 灾情图像 > 报平安短信。
- 复用 Rel-17 GNSS + 星历开环预补偿，四步压两步（MsgA 内嵌认证/业务字段，MsgB 确认指配）。
- 预补偿失败回退四步的逻辑与统计口径见开放疑问 Q8。

### 2. 安全侧 T4 — 认证机制（方向 C）
- **首次接入（双根预置 + 星侧受灾判定 / Q4 决议）**：终端与卫星直连、**卫星侧探测信关不可达（确认灾区）**后，终端先出示**设备根身份**（出厂/eSIM 预置）经卫星校验，卫星作为在轨 KGC 下发 CL-PKC 部分私钥 + 假名（用星座根签名）；该 ephemeral 凭证任意卫星可直验，无需 ISL。对应文献 EDHOC-NTN（CL-PKC 取代 IPSec）。
- **后续每次切换**：哈希链续认证（轻量，星上仅一次比对）；续认证所需认证上下文由 **星历预测驱动提前准备**。
- **动态匿名标识（假名）轮换**：与切换事件 / 时隙绑定（具体触发见 Q2）。
- **溯源文献**（均带可访问 URL）：
  - EDHOC-NTN：CL-PKC 无证书 + EDHOC 轻量 AKA，省 56% 带宽 — [中国科学 2026 PDF](http://scis.scichina.com/cn/2026/SSI-2025-0464.pdf)
  - SEHAP：LEO NTN 切换认证 + 安全上下文迁移 — [IEEE 2024](https://ieeexplore.ieee.org/document/10887616/citations)
  - Kwon 2025：STIN 切换认证，ECC 初始 + hash/XOR 切换，ns-3 仿真 — [IEEE TIFS 2025](https://doi.org/10.1109/TIFS.2025.3628470)
  - Modified AKMA：去中心化连续认证、抗 UAV 仿冒 — [IEEE IoT-J 2025](https://doi.org/10.1109/JIOT.2025.3526635)
- **排除项**（与 AGENTS.md §0.4 一致）：区块链 / 跨域 PKI / 物理层指纹实现 / 群组聚合认证。

### 3. 切换侧 T5~T8 — 认证上下文预迁移通路
- **通路 = 终端携带令牌**：切换重连时终端把安全上下文令牌呈交目标星；**v1 不建模 ISL**，不依赖灾后已瘫信关。
- **安全上下文优先迁移**（喂 T7 一次比对）；承载上下文（喂 T8）v1 暂缓（见 Q11）。
- **目标星 ID 校验 + 预测失配兜底**，呼应指标「预测失配率」。
- 与 T4 的耦合：推送/携带内容必须经 T4 协议签名 / 加密（"只有目标星能解"），新星用 T4 凭证根独立复核，不盲信前星。

### 3.1 T2 切换对比矩阵（2026-09-16 定稿；5 基线 + 1 消融臂）

> **需求**：对比方法 = 1 本职 + 2 现代化业内常用 + 2 近年论文算法；业内项取「本方向已落地」、论文项取「与本项目机制正交（不与消融实验雷同）且期刊等级高 + 时间最近」。

| # | ho_policy | 类别 | 来源 | 关键机制 |
|---|---|---|---|---|
| 0 | `predictive` | 本职 | 本项目（2026） | 星历预测 + 先建后断 + 星间认证上下文预迁移（RACH-less） |
| 0′ | `predictive_nopremig` | **消融臂（非基线）** | 本项目（2026） | 与 0 同提前量/同候选选择，**仅关闭预迁移**（切换重 RACH）——用于分离归因 |
| 1 | `cho` | 业内① | 3GPP Rel-16/17 条件切换（TS 38.331） | 时间型条件触发（先建后断），无预迁移 |
| 2 | `rel17` | 业内② | 3GPP Rel-17 NTN 标准 | 反应式（无预测提前量）+ 四步 RACH（已部署标准） |
| 3 | `dqn` | 论文① | N. Badini, M. Jaber, M. Marchese, F. Patrone, "User-Centric Satellite Handover for Multiple Traffic Profiles Using Deep Q-Learning," **IEEE TAES** 60(6):8591–8604, 2024. DOI:10.1109/TAES.2024.3434771 | DQN 多业务选星（学习型） |
| 4 | `graph` | 论文② | S. Eydian, M. Hosseini, G. Karabulut Kurt, "Handover Strategy for LEO Satellite Networks Using Bipartite Graph and Hysteresis Margin," **IEEE OJCOMS** 6:1470–1484, 2025. DOI:10.1109/OJCOMS.2025.3541962 | 加权二部图 + Kuhn-Munkres 匹配 + 滞回边 |

**选型说明**
- 业内项：**DAPS 排除**——3GPP 明确 NTN 不支持 DAPS，不属「本方向已落地」；Rel-17 NTN 是 NTN 已标准化/在部署的移动性标准，最贴判据。
- 论文项：**弃用** Wu et al. INFOCOM 2024（星历预测，降时延 10×）与 2024 GRU-PCHO——二者均为**预测式**，与本项目 `predictive` 同族，会被判为「本项目自己的消融实验」；改用机制正交的**学习型(DQN)** 与**组合优化型(Graph-KM)** 基线。
- 实现忠实度（诚实披露）：`predictive`/`cho`/`rel17` 为机理忠实实现；**`dqn` 为 DQN 收敛策略的确定性等价**（非在线神经网络、非论文的 MADQN 集中训练），仅作机制对照、不与论文比绝对数值；**`graph` 在本模型（无卫星容量约束）下 KM 数学退化为加权 argmax**，其可实现杠杆仅「负载惩罚 + 滞回边」，故定位为**近似实现**（负载项为弱归一、不 binding，见 §3.5 调查结论）。

**消融臂用途与实证结论（★2026-09-16★）**：`predictive_nopremig` 与 `predictive` 实测**切换中断完全相同（均 ≈0.01 ms）**，仅切换总时延不同（**381.0 vs 12.1 ms**）、预迁移命中率 0 vs 1.0。据此**更正归因**：
- **切换中断归零** ← **预测提前量下的先建后断重叠窗**（20s ≫ 一次重连 ~381ms）；
- **切换时延 ↓97%** ← **星间认证上下文预迁移（RACH-less）**。

原「预迁移使中断下降 ~100%」的表述不准确，已同步更正（见 `docs/学术基线对照.md` §2.1）。

### 3.2 T3 接入握手对比矩阵（2026-09-16 定稿，3 方案）

> **需求**：对比方法 = 1 本项目自身 + 1 最新已落地现代化基线 + 1 最新论文且贴合项目的方法。

| # | `rach_scheme` | 类别 | 来源 | 关键机制 |
|---|---|---|---|---|
| 0 | `twostep_precomp` | 本项目 | 本方案 | 两步 RACH + GNSS/星历开环 **TA 预补偿**（免前导竞争、握手短） |
| 1 | `rel17_4step` | 已落地基线 | 3GPP Rel-17 NTN（2022） | 四步 RACH：前导竞争 + RAR 窗口 + 竞争解决定时器 + 4×几何往返 |
| 2 | `msgarep_2step` | 论文方法 | T. Kim et al., "Two-Step Random Access With Message Replication for LEO Satellite Networks," **IEEE WCL** 2025 | 两步 RACH（存在 MsgA 前导冲突）+ **M=4 份 MsgA 副本**，任一份避开冲突即成功 |

**选型说明**
- 本项目用「TA 预补偿**消除**冲突源」，论文用「副本分集**缓解**冲突」——二者**机制正交**，不会被判为本项目消融。
- 实现在 `sim/protocol.py` 新增 `rach_scheme` 参数（`MSGAREP_M`/`RACH_SCHEMES` + 接入段三方案分派），**不改既有 `rach_steps` 语义**（向后兼容）。

**容量记账决策（2026-09-16 补，`RACH_SLOT_UNITS`）**

- **问题**：时隙准入 `_slot_ok()`（`rach_capacity=4`/10ms）原先对所有方案扣减 1 单位，致**成功率只由容量上限决定、与接入方案无关**（实测三方案均 0.7234），T3 失去区分度。
- **决策**：按方案扣减容量单位 —— `twostep_precomp`=1（MsgA 一次占用）、`rel17_4step`=2（Msg1+Msg3）、`msgarep_2step`=M=4（M 份副本）。
- **依据**：3GPP 两/四步 RACH 的信道占用次数不同；副本分集的资源代价是论文自身承认的权衡。两轨（`sim/protocol.py` 与 `.ns3_ref/leo_access.cc` 的 `slotOk(..., units)`）对称实现。
- **敏感度（诚实披露）**：把副本单位改回 1 时 msgarep 成功率 = **0.7217**（≈本项目 0.7234），即其低值来自 **×M 资源开销**而非冲突模型。故结论表述为：**灾后窄带容量受限场景下资源效率主导**，与 `AGENTS.md` §0.3「星上轻量化」约束一致。

**变量隔离对照（2026-09-16 补，闭合上条「可选扩展」，含与预期相反的实测结论）**

- **动因**：窄带场景把 msgarep 压成全场最差，评审易误读为「论文方法就是更差」；须做**变量隔离**才能判断是哪个变量在起作用。
- **做法**：逐步隔离一个变量（其余一字不改），共 3 场景 × 3 方案 × 2 轨（`exp/t3_access/run_t3.py`）：

| 场景 | 隔离的变量 | 成功率（双轨，twostep / rel17 / msgarep） | 结论 |
|---|---|---|---|
| `wenchuan_storm2` | —（窄带 `rach_capacity=4`） | 0.7234/0.4083/**0.158**（ns-3 0.699/0.445/0.205） | 容量受限 → **资源效率主导**，msgarep 因 ×M=4 最差 |
| `wenchuan_storm2_wide` | 容量（4→256） | **1 / 1 / 1** | 容量不 binding 时 msgarep **时延恢复到 13.3/14.8 ms**（≈本项目 12.4 ms）→ 证明其窄带劣势**纯来自 ×M 资源代价**，非机制无效 |
| `wenchuan_storm2_contend` | 前导冲突（64→8 前导） | 1 / 0.9561/**0.8025**（ns-3 1/0.942/0.765） | ★与预期相反★ msgarep **低于** rel17_4step |

- ★**关键实测结论（据实记录）**★：在**忠实资源记账**下（M=4 份副本各占**独立**前导资源），把前导冲突变成主导失败源后，msgarep 成功率**反而低于** `rel17_4step`（0.80/0.77 vs 0.96/0.94）——副本的**资源外部性**（多占 4 份前导、加剧全体冲突）**抵消**了其**分集增益**。
  → 即 **Kim et al. (WCL 2025) 的副本分集在「副本各占独立资源」这一忠实解释下，于本模型/本负载区间不占优**；这是本项目的**实证结论**，不是实现缺陷。若论文原意是「副本复用同一前导、仅在时/频上重复载荷」，则资源外部性会小得多——该解释差异已在 `exp/t3_access/README.md` §三 与 §七 显式披露。

**时延口径修正（2026-09-16 补，★必读★）**

- **问题**：契约 2.1 的 `接入时延均值_ms` **只统计成功终端**（失败事件 `value_ms=-1` 不入均）。三方案成功率差异极大（0.72/0.41/0.16）时，直接横比时延存在**幸存者偏差**——msgarep 的低均值只覆盖少数"快速成功"终端；实测两轨时延**排序相反**（Python：msgarep 116.5 < twostep 193.5；ns-3：twostep 225.4 < msgarep 282.5），即该偏差已使结论不可跨轨复现。
- **决策**：① 时延指标**显式标注「仅成功终端」口径**；② 跨方案比较**必须并读** `接入成功率` 与 `RACH吞吐_终端每秒`（二者无该偏差，两轨排序一致）；③ 文档中删除「两轨时延排序逐项一致／本项目最短」的**失准表述**（原 `exp/README.md`、`exp/t3_access/README.md` 已更正）。
- **不做的**：不改 trace 契约新增列（成本/风险高于收益）；若后续需要严格可比的"含失败"时延，应走**等成功率口径**或**负载扫描曲线**。

### 3.3 双轨可见性同源（方案 A，2026-09-16 定稿）

- **问题**：Python 轨用「场景中心点」窗服务全部终端，ns-3 轨按「每终端位置」各算窗 → 终端铺开 ±0.6°(≈±67km) 时两轨边界判定翻转，造成中断尾部/切换次数不一致（原 T2 残差②③④ 同源）。
- **决策**：终端**吸附**到同一 5×5 格点（中心 ±{0,±0.3°,±0.6°}），Python 算 25 个格点窗写入 `data/sim/ns3_in/grid_windows.csv`，**两轨读同一份**（ns-3 侧 1200/1200 命中，缺文件时回退自算并告警）。
- **理由**：窗集只依赖格点中心 ⇒ 两轨可见性**逐字一致**；避免两轨各自实现吸附逻辑产生浮点分歧。
- **效果**：`cho` 中断均值 Py 15.76 / ns-3 15.29 ms（原 0.09 / 26.4）；切换事件数缺口由 8–10% 收窄至 1.1–3.6%。
- **代价**：Python 每轮多算 25 次 `compute_access`（实测 ≈4s）；ns-3 每轮写一次窗文件（同源计算）。
- 完整说明见 `exp/方案A_网格窗实现说明.md`。

### 3.4 乒乓指标构成分解（2026-09-16，调查后不改算法）

- **现象**：本职 `predictive` 乒乓率 **4.13%**，高于全部基线（`cho` 0.04%、`rel17`/`dqn`/`graph` ≈0），与 T6「抑制乒乓」的叙事看似矛盾。
- **调查（`exp/diag_pingpong.py`，按终端重放切换序列）**：predictive 相邻切换间隔**中位 289.7s**（正常），但 **4.22% 的间隔 <10s（最小 0s）**；乒乓事件全部来自「间隔<30s」分量，切回分量另有 3.34%。
- **修复尝试（实证失败，已撤回）**：引入「候选最小剩余可见时长 `HO_MIN_CAND_RESID_S`」过滤——阈值 **50s 时数值逐位不变**（病态情形下唯一可见候选即短临空窗星，无更优可换）；阈值 **400s 时切换数 14931→10399，但中断 0.01→1.88ms、乒乓 4.13%→5.82% 反而变差**。→ 说明这些快速连切是**「切入短临空窗星接力」以维持零中断的代价**，属设计权衡而非缺陷，**故不改算法**。
- **决策（改为指标层如实呈现）**：在 `sim/eval.py`（唯一指标实现，双轨共用）新增乒乓**构成分解**——
  | 指标 | 含义 | predictive 实测 |
  |---|---|---|
  | `乒乓切换率` | 原合并判据（切回 ∪ 间隔<30s） | 0.0413 |
  | `乒乓_快速连切率` | 相邻切换间隔 < `PINGPONG_MIN_GAP_S` | 0.0413 |
  | `乒乓_切回率` | 窗口内切回曾服务过的星（T6 真正要抑制的对象） | 0.0334 |
- **口径说明**：predictive 的乒乓几乎全部是**快速连切**分量——这是它用「多切一次」换取「零中断」的**显式代价**，应在报告中与 `切换中断均值` **并读**，而非单独作为缺陷指控。基线（如 `rel17`）乒乓为 0 是因为其**不提前切换**（LOS 末端强制切），代价是中断 380.5ms。

### 3.5 graph 基线「负载项 binding 化」尝试（2026-09-16，判定净负面并撤回）

- **问题**：`graph`（Eydian et al., OJCOMS 2025）的负载惩罚项因归一化分母过大（累积负载/终端总数）而近似常数、**不 binding** → 结果与 `cho` 近乎同质（Py 中断 16.18 vs 15.76 ms）。
- **尝试**：改「瞬时负载」（离开旧星 -1／接入新星 +1）+ 按**当前峰值负载**归一，使惩罚项达 `GRAPH_LOAD_PEN`(0.15) 量级。
- **实测结果（净负面）**：
  | 指标 | 改前 | 改后 |
  |---|---|---|
  | graph 中断均值（Py / ns-3） | 16.18 / 15.25 ms | **112.2 / 15.25 ms（★两轨发散★）** |
  | graph 中断最大（Py） | 412.1 ms | **60420 ms（60.4 s）** |
- **判定**：负载状态随终端连接序列演化，一旦惩罚项 binding 就会**放大两轨独立 RNG 的差异**，使 `graph` 失去双轨可复现性；且 `graph` 是**基线**，把它做差在方法学上不可取。→ **已完全撤回**（Python + ns-3 双轨）。
- **结论**：`graph` 保留「加权 argmax + 滞回 + 弱负载项」的**近似实现**，并在代码注释与 §3.1 显式标注为近似；不再试图用负载项制造与 `cho` 的区分度。
