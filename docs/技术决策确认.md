## 〇、一句话锁定

- **接入侧（T3）**：突发风暴优先级保障 = 高优先级前导码分组 + 调度优先服务（混合式）。
- **安全侧（T4）**：认证机制 = **方向 C 混合**——初始接入用无证书公钥（CLC / CL-PKC）强认证（一次性，双根预置 + 星侧受灾判定，见 Q4）+ 后续切换用哈希链轻量续认证；续认证上下文由星历预测驱动提前准备；动态匿名标识（假名）轮换。具体算法（2026-09-01 决议）：**EC-Schnorr CL-PKC**（星=在轨 KGC、主私钥不传星）；假名**每次切换轮换**；哈希链**首联 MsgB 下发种子 + 索引单向递增**；令牌**复用星座根 kid 签名**（任意目标星直验）。
- **切换侧（T5~T8）**：认证上下文预迁移通路 = **终端携带令牌（terminal-carried token）**；v1 不建模星间链路（ISL）、不依赖灾后已瘫的信关站。

## 一、三招已确认决策

### 1. 接入侧 T3 — 突发风暴优先级保障
- **机制**：高优先级前导码分组 + 调度优先服务（混合式，非纯排序、非纯预留）。
- 优先级 = f(业务优先级, 终端位置危险度)；业务三档：指挥话音 > 灾情图像 > 报平安短信。
- 复用 Rel-17 GNSS + 星历开环预补偿，四步压两步（MsgA 内嵌认证/业务字段，MsgB 确认指配）。
- 预补偿失败回退四步的逻辑与统计口径见开放疑问 Q8。

### 2. 安全侧 T4 — 认证机制（方向 C）
- **首次接入（双根预置 + 星侧受灾判定 / Q4 决议）**：终端与卫星直连、**卫星侧探测信关不可达（确认灾区）**后，终端先出示**设备根身份**（出厂/eSIM 预置）经卫星校验，卫星作为在轨 KGC 下发 CL-PKC 部分私钥 + 假名（用星座根签名）；该 ephemeral 凭证任意卫星可直验，无需 ISL。对应文献 EDHOC-NTN（CL-PKC 取代 IPSec）。
- **后续每次切换**：哈希链续认证（轻量，星上仅一次比对）；续认证所需认证上下文由 **星历预测驱动提前准备**。
- **动态匿名标识（假名）轮换**：与切换事件 / 时隙绑定（具体触发见 Q2）。
- **溯源文献**（均带可访问 URL）：
  - EDHOC-NTN：CL-PKC 无证书 + EDHOC 轻量 AKA，省 56% 带宽 — [中国科学 2026 PDF](http://scis.scichina.com/cn/2026/SSI-2025-0464.pdf)
  - SEHAP：LEO NTN 切换认证 + 安全上下文迁移 — [IEEE 2024](https://ieeexplore.ieee.org/document/10887616/citations)
  - Kwon 2025：STIN 切换认证，ECC 初始 + hash/XOR 切换，ns-3 仿真 — [IEEE TIFS 2025](https://doi.org/10.1109/TIFS.2025.3628470)
  - Modified AKMA：去中心化连续认证、抗 UAV 仿冒 — [IEEE IoT-J 2025](https://doi.org/10.1109/JIOT.2025.3526635)
- **排除项**（与 AGENTS.md §0.4 一致）：区块链 / 跨域 PKI / 物理层指纹实现 / 群组聚合认证。

### 3. 切换侧 T5~T8 — 认证上下文预迁移通路
- **通路 = 终端携带令牌**：切换重连时终端把安全上下文令牌呈交目标星；**v1 不建模 ISL**，不依赖灾后已瘫信关。
- **安全上下文优先迁移**（喂 T7 一次比对）；承载上下文（喂 T8）v1 暂缓（见 Q11）。
- **目标星 ID 校验 + 预测失配兜底**，呼应指标「预测失配率」。
- 与 T4 的耦合：推送/携带内容必须经 T4 协议签名 / 加密（"只有目标星能解"），新星用 T4 凭证根独立复核，不盲信前星。

## 三、开放疑问清单（待负责人拍板，AI 不替你定方案）

### 认证侧（T4）
- **Q1 ✅ 已决议（2026-09-01）：CLC/CL-PKC 构造 = EC-Schnorr CL-PKC**；星作为在轨 KGC 仅持主公钥 + 下发部分私钥，主私钥不传星（防星被控全盘泄露）；完整私钥 = 终端秘密值 + 部分私钥。
- **Q2 ✅ 已决议（2026-09-01）：假名 tid 轮换触发 = 每次切换轮换**（与可预测切换天然耦合，前向不可关联最强）。
- **Q3 ✅ 已决议（2026-09-01）：哈希链 = 首联 MsgB 下发种子 + 索引单向递增**；星上 (tid→idx,sn) 轻量表 LRU + 周期超时淘汰，天然防重放（R6）。
- **Q4 ✅ 已决议（2026-09-01， refined 双根模型）**：采用**双根预置 + 星侧受灾判定**模型，发射/出厂前预置、**不依赖灾时核心网**：
  1. **卫星侧根**：星座共享根密钥（运营商发射前烧入每颗星）→ 任意卫星可直验其他星签发的令牌，**无需 ISL、无需实时告知邻居**（解决原 R3）。
  2. **终端侧根**：设备根身份（出厂/eSIM 烧录的设备证书或根密钥，类比 IMSI/Ki）——即"发证授权根"，终端首联**必须先证明它**才获证（解决原 R1）。
  3. **受灾判定 = 星侧可观测量**：卫星探测"信关/核心网不可达"才进入灾区模式发证，非终端自述，攻击者无法伪造（解决原 R2）。
  - **首联流程**：终端直连 → 卫星确认信关不可达（星侧）→ 终端出示设备根身份（签名）→ 卫星校验 → 卫星作为在轨 KGC 下发 CL-PKC 部分私钥 + 假名，并用**星座根签名** → 拿到 ephemeral 运营凭证。
  - **切换**：终端携令牌（签发星用星座根签名）→ 目标星用星座根**直接验**，无需邻居已被通知；"告知周围卫星"降级为可选缓存预热。
  - **伪造终端**：无设备根身份 → 首联校验不过 → 发证阶段即拦截（呼应「伪造终端拦截率」）。
  - 与方向 C 衔接：卫星=在轨 KGC（下发部分私钥），终端自生成秘密值 + 部分私钥 = 完整 CLC 私钥；单根签名验证对星上算力极轻，不违反 AGENTS.md §0.3/§0.4（星座根≠完整在轨 PKI）。
  - **v1 落地约束**：v1 不建模 ISL/信关；本模型本就不依赖 ISL（令牌任意星直验），故与 v1 完全兼容。
- **Q5 ✅ 已决议（2026-09-01）：令牌信封签名 = 复用星座根 kid 签名**（与双根模型一致，无额外密钥管理，任意目标星直验；令牌以签名认证、v1 不要求机密性）。加密到目标星留未来增强。

## 三·C、已决项风险提示（已决定但可能有坑 / 需复核）

即便已拍板的方向，也有几处"决定本身成立、但落地时会反噬"的点，列出供负责人复核：

- **R1 ✅ 已解决（双根模型）**：终端侧根（设备根身份，出厂/eSIM 预置）即"发证授权根"——首联须先证明设备身份才获证，伪造终端无此根 → 发证阶段即拦。详见 Q4 决议。
- **R2 ✅ 已解决（双根模型）**：受灾判定改为**星侧可观测量**（卫星探测信关/核心网不可达），非终端自述，攻击者无法伪造。详见 Q4 决议。
- **R3 ✅ 已解决（双根模型）**：星座共享根密钥使任意卫星可直验令牌，**无需 ISL、无需实时告知邻居**；"告知周围卫星"降级为可选缓存预热，v1 完全兼容。详见 Q4 决议。
- **R4 ⚠️ 风暴下发证成瓶颈**：Q4 让卫星在首次接触时为每个终端做密码学发证。突发风暴下成百上千终端同时首联，星上发证队列可能成为"接入时延 / 认证引入额外时延"的新尖峰——需把发证时延单独建模进指标，并考虑分级（高优先级先发证）。
- **R5 🔶 "方向 C 首次 CLC 强认证"与"卫星生成凭证"的措辞对齐**：方向 C 原话是"终端用 CLC 强认证"，Q4 决议改为"卫星生成并下放凭证"。二者在 CL-PKC 下可统一（卫星=KGC 下发部分私钥），但**终端仍需先持有自生成秘密值 + 经 R1 根信任**，并非"卫星单方面生成一切"。文档措辞已在上文 §一.2 修正，复核是否到位。
- **R6 🔶 终端携带令牌的信任边界**：令牌经终端之手，恶意终端可截改/重放——已靠"T4 协议签名 + 目标星 ID 校验 + 预测失配即弃"缓解，但**重放已过期令牌**的防护（哈希链索引单向性）须由 Q3 种子/索引设计兜底，否则先建后断可被重放攻击。

> 以上 R1~R3 与 Q4 强相关，建议在 T4 方案设计（人主导）时最先澄清；R4 进指标建模；R5~R6 进协议细节。
