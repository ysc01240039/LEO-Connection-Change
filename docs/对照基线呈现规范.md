# 对照基线呈现规范（借鉴学术论文与标准化落地实践）

> 用途：把「论文科研」与「标准化/商业落地」两套主流的**性能对比呈现样式**落成本项目可执行的检查清单，
> 用于 T2/T3 对照表的排版、统计与自证公平性。
> 日期：2026-09-22｜性质：**参照业界样式的落地建议**——凡标注 `[可调整]` 的条目均可按评审反馈与工期取舍，**不改动仿真方法本身**。
> 配套：`docs/技术决策确认.md` §3.1/§3.2（基线选择定稿）、`docs/学术基线对照.md`（文献出处与增量）、`docs/双轨交叉验证对照表.md`（数字唯一出处）。

---

## 一、两套权威样式来源

### 1.1 学术论文侧（AI / 系统类顶会审稿共识）

| 样式条目 | 惯例要求 |
|---|---|
| 基线数量 | **≥ 6 个对比方法**（经典方法 + 近 1~2 年 SOTA + 自己的消融 variant） |
| 公平比较 | 同一 backbone / 同一训练与评估配置（禁止"A 方法用 ResNet、B 方法用 ViT"式 cherry-pick） |
| 表格排版 | **本方法加粗、次优结果加下划线**（学术界约定俗成，不遵守会被认为不专业） |
| 统计检验 | 关键提升补 **t-test 或 Wilcoxon** 显著性检验，说明提升不是随机波动 |
| 方差报告 | **多种子** 取 mean ± stdev / 置信区间；**单次运行被视为轶事（anecdote）** |
| 消融 | **控制变量**：每次只去掉或替换一个模块，观察性能变化 |
| 效率透明 | 时延 / 吞吐 / 内存 / 算力等资源指标显式报告，并说明**权衡**（收益是否以资源为代价） |
| 可复现 | 数据来源、版本、seed、运行次数、代码可达性 |
| 诚实解释 | 差异小/他法更好的情形要写原因，不夸大、不隐藏负向指标 |

> 关键告诫：**弱基线（straw man）与缺失统计是审稿人最主要的攻击面**——"选一个明显弱于预期的基线"会被直接质疑。

### 1.2 标准化 / 商业落地侧（3GPP NTN 评估方法学，TR 38.821）

| 样式条目 | 惯例要求 |
|---|---|
| 参考场景固定 | 六参考场景（A=GEO 透明 / B=GEO 再生 / C1·C2=LEO 透明 / D1·D2=LEO 再生），LEO-600/1200、S/Ka 频段 |
| 参数表固定 | SLS 参数（EIRP 密度、天线、带宽、UE 特性、复用因子…）成表固化，逐条可核对 |
| 校准（calibration） | 30 个公共校准案例（Table 6.1.1.1-9），多公司曲线互相对齐后才有资格报性能 |
| 分位数指标 | 报 **5% / 50% / 95% 分位**吞吐（@RU%），**不是单点均值** |
| 未定项显式声明 | 不确定项写明 "To be reported by the companies"——即**把可调项摆在明面上**，而不是隐去 |

## 二、本项目现状 × 规范对照

| # | 样式条目 | 本项目现状 | 判定 | 处置 |
|---|---|---|---|---|
| 1 | 基线数量 ≥6（学术惯例） | T2 = **5 基线 + 1 消融臂**；T3 = 3 方案 | ⚠️ 低于惯例 | `[可调整]` 候选见 §三.A |
| 2 | 公平同配置（禁止做差基线） | 存在 **`RACH_SLOT_UNITS` 记账差异**（四步=2 / 副本=M=4）——§3.2 已披露 | ⚠️ 需自证公平 | `[可调整]` 补 units=1 公平性对照臂（§三.B） |
| 3 | 本方法加粗、次优下划线 | README §9 表格**未使用**该约定 | ⚠️ 未落地 | `[可调整]` 排版即可（§三.C） |
| 4 | 显著性检验（t/Wilcoxon） | 有 3 种子 mean±stdev，**无显著性检验** | ⚠️ 缺 | `[可调整]` 对关键提升补检验（§三.D） |
| 5 | 多种子 + 置信区间（单次=轶事） | 对照/消融/敏感性 **3 种子 ✅**；**主结果（§9.1）为 `reps=1` 单种子** | ⚠️ 部分缺 | `[可调整]` 主结果提为多种子（§三.E） |
| 6 | 消融控制变量 | `--ablation` 逐级翻转接入/切换范式 ✅ | ✅ 符合 | — |
| 7 | 效率透明 + 权衡 | 接入时延、RACH 吞吐、认证时延、切换时延均报告；低危吞吐损失显式声明为取舍 ✅ | ✅ 符合 | — |
| 8 | 可复现（seed/版本/次数/代码） | run `manifest.json`（seed/commit/场景快照/TLE 溯源）+ trace + 台账 ✅；**ns-3 传播历元未固定（同 seed ~0.2% 漂移）** | ⚠️ 部分 | `[可调整]` 固定历元（§三.F） |
| 9 | 诚实解释（小差异/负向指标） | §9.6 局限、§3.5 graph 近似实现、负向指标隔离量化 ✅ | ✅ 符合 | — |
| 10 | 分位数指标（标准化侧） | 接入时延已报 **P95**；切换中断**仅报均值** | ⚠️ 部分 | `[可调整]` 中断补 P95（§三.G） |
| 11 | 校准 / 互相对齐（标准化侧） | **双轨交叉验证对照表**即本项目版"自校准"（同参、同种子、同口径，逐位/≤1.1% 对齐）✅ | ✅ 符合 | — |
| 12 | 可调项显式声明（标准化侧） | 本文档 + `技术决策确认.md` §3.1/§3.2 已显式登记可拓展项 ✅ | ✅ 符合 | — |

**结论**：**9 条符合或部分符合，3 条需补**（#1 数量、#2 公平性自证、#4 显著性检验），其余为排版/口径级的低风险调整。全部缺口的处置成本与优先级见 §三。

## 三、可调整项（`[可调整]`，按性价比排序）

| 标号 | 事项 | 具体做法 | 成本 | 优先级 |
|---|---|---|---|---|
| **A** | 基线数量补足至惯例（≥6） | 候选：① 3GPP Rel-18/19 NTN 移动性增强（标准，已落地）；② 论文：grant-free / 2025 新切换算法（**须检索真实文献出处，不许自编**） | 中 | ★★☆ |
| **B** | 公平性对照臂（自证不做差基线） | `rel17_4step` / `msgarep_2step` 在 `RACH_SLOT_UNITS=1` 下重跑，与默认口径并列成表——**回应"部分基线与本方案差距过大疑实现问题"** | 小 | ★★★ |
| **C** | 表格排版约定 | README §9 及对照表：**本方案加粗**、次优**下划线** | 小 | ★★★ |
| **D** | 显著性检验 | 对 headline 提升（接入时延 / 高危成功率 / 切换时延）补 Wilcoxon 或配对 t 检验，标注 p 值 | 小 | ★★☆ |
| **E** | 主结果多种子 | §9.1 主结果由 `reps=1` 提为 `--reps 10`，出 mean±95%CI（同时满足存档规范 §三"≥10 次重复"） | 中 | ★★★ |
| **F** | ns-3 传播历元固定 | 把 SGP4 传播历元锚定为固定时刻（配置项），消除 ~0.2% 同 seed 漂移 | 小 | ★☆☆ |
| **G** | 中断分位数 | 切换中断补 P95，与接入时延口径一致（对齐 3GPP 分位数呈现惯例） | 小 | ★☆☆ |

> ⚠️ 说明：A/B/E/F 会触及"仿真环境参数或实验规模"，与用户先前的"不考虑仿真环境进一步真实化"取向**部分重叠**——A/F 属参数与复现性、B/E 属对照公平性与统计严谨性，均为"让已有机制与对照更站得住"，**不新增物理层真实化**。是否执行由项目负责人按评审与工期决定。

## 四、执行约定（落地约束）

1. **图表三要素缺一不可**：数据来源（`run_id`）+ 对比基线 + 一句话结论（缺一项不进答辩材料）；
2. **数字只有唯一出处**：`docs/双轨交叉验证对照表.md`（不从 commit message 或不具名运行记录抄数字）；
3. 新增/调整对照时，**同步更新**：`技术决策确认.md` §3.1/§3.2（选择与判据）、`学术基线对照.md`（文献出处与增量）、`双轨交叉验证对照表.md`（数字）、本规范的 §二 对照表；
4. 每条对照方法必须可复现：命令行 + seed + run 目录 + trace 齐全。
