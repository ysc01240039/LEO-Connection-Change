## 三、差距逐项分析（按计划书模块）

### 3.1 模块三·方向二：生存优先分级接入 —— ⚠️ 只打标、未调度（真实偏离）
- **计划书要求**：业务优先级 + 终端危险度 → 综合优先级函数；高优先级用专用导频/前导码，保障"最危险的人先接入"。
- **当前实现**：`sim/scenario.py` 按 `danger_tags` 概率给终端**打 high/med/low 标签**（`sim/protocol.py:227-232`），但该 `tag` 字段在两轨**全程仅透传**，无任何 `if tag` 分支驱动资源分配/前导码分组/接入顺序。
- **影响**：计划书"温度"创新点（价值调度）目前**无实验支撑**，答辩会被质疑"标签画了没用"。
- **修复成本**：中（需在前导码分组 + 接入排序 + 退避中引入 tag 权重；ns-3 轨镜像）。

### 3.2 模块五：ns-3 含卫星/NTN 模块 —— ⚠️ 退路已用，未达"硬要求"
- **计划书要求**：底层协议级仿真采用 **ns-3（含卫星/NTN 模块）**。
- **当前实现**：WSL `ns-3-dev/src/` 仅标准模块（antenna/applications/lr-wpan/uan…），**无 satellite/ntn/nr**；当前 `.cc` 为自研 LEO 信道 + 自定义协议状态机，**属计划书 §十二 风险应对明列的退路**——"若进度受阻，该部分可退化为 Python 侧建模复现 / 自研 ns-3 模型"。
- **影响**：协议保真度低于真实 NTN 栈；但若答辩口径为"自研 ns-3 模型已交叉验证"，可接受。属** fidelity 升级而非正确性缺口**。
- **修复成本**：高（见第四节安装评估）。

### 3.3 模块五：Web 可视化演示 —— ❌ 缺失（计划书硬交付物）
- **计划书要求**：ECharts/Three.js 展示星座运行、波束覆盖、接入/切换事件、时延统计；数字孪生推演沙盘。
- **当前实现**：仅 matplotlib 静态 PNG + 自包含 HTML 报告（`sim/viz.py`）。无交互、无三维、无 ECharts。
- **影响**：**预期成果"数字孪生推演系统(1套)"未达成**；结题/答辩演示材料缺口明显。
- **修复成本**：中（Node.js 已可用；需搭前端 + 对接 `metrics.json`/`access_trace.csv`）。

### 3.4 量化指标表述 —— ⚠️ 未固化为"相对基线提升%"
- **计划书 §4.1 / §十二**：指标须以"相对基线的提升百分比"表述（时延↓30%+、成功率↑20%+、中断↓40%+）。
- **当前实现**：已有两步 vs 四步、storm2 vs storm4 的绝对对比，但**未把"相对 Rel-17 四步基线的提升%"写成固定结论字段**。
- **影响**：答辩最关心的三个数字未以计划书口径固化，易被追问。
- **修复成本**：低（在 `eval.py` 加基线引用 + 百分比输出）。

### 3.5 认证机制形态 —— ✅ 与计划书一致（与 T4 伪代码草图有出入，但草图非权威）
- **计划书 §模块三·方向四**：明确写"**预共享凭证 + 一次性令牌，星上仅做本地比对验证**"。
- **实现**：`sim/auth.py` 用 HMAC-SHA256（=预共享密钥 + 令牌 MAC）+ 重放检测 + 派生假名，**与计划书文字完全一致**。
- **说明**：`docs/T4协议伪代码草图.md` 写的 EC-Schnorr/CL-PKC 与计划书文字**不一致**；当前 HMAC 实现反而更贴合计划书。若答辩要求"密码学深度"，再升级到 CL-PKC 属扩展，非缺口。

### 4.2 唯一待装项：ns-3 卫星/NTN 模块（SNS-3 / 5G-LENA）
| 维度 | 评估 |
|---|---|
| 网络可达性 | github 主页可达(200)，但 **SNS-3/5G-LENA 旧 github 地址已全部 404**（仓库已迁 gitlab）；`gitlab.com/ns3-ntn-toolkit` 可达（已在 `vendor/` 存过） |
| 版本对齐风险 | WSL 为 **ns-3.48**；SNS-3/5G-LENA nr 通常锁定 ns-3.40–3.42，**直接合入 .48 大概率需改接口/打补丁** |
| 构建成本 | 克隆 + 编译 nr(5G-LENA) 约 **多 GB、30–90 分钟**（C++ 全量重编） |
| 收益 | 协议保真度↑（真实 NTN RACH/TA/波束）；但**不改变已验证的核心结论**（两步/四步、预测切换、认证判别力） |
| 计划书定位 | 属"硬要求"但**已有明列退路**（自研 ns-3 模型 / Python 复现） |
