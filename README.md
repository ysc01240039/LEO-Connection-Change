## 一、项目应对场景

### 1.1 要解决的具体问题

本项目针对灾后通信完全失联这一极端场景。地震、山洪等重大灾害摧毁地面通信基础设施后，公网基站、核心网（AUSF/UDM/HSS 等网元）、卫星信关站可能同时瘫痪。此时：

1. 传统地面蜂窝网络不可用，受灾群众与救援队伍的通信需求集中爆发；
2. 依赖地面设施转发验证的卫星间接认证流程不可用，终端无法沿用常规入网鉴权；
3. 受灾终端只能直接连接低轨（LEO）卫星，而 LEO 卫星相对地面高速运动（约 7.5 km/s），单星可见窗口仅数分钟，接入建立后不久即面临频繁切换；
4. 海量终端在极短时间内集中发起接入（呼叫风暴），随机接入信道（RACH）发生碰撞风暴，接入时延与失败率急剧恶化；
5. 星上算力与存储资源有限，无法承载重型安全协议或复杂调度机制。

项目要解决的核心问题可归纳为三点：在海量终端集中、突发发起接入的情况下，如何让终端快速、可靠地接入低轨卫星网络；如何在无核心网条件下完成星上本地轻量认证，使伪造终端可拦截、合法身份可保护；如何实现切换低中断的可预测跨星切换。

### 1.2 目标用户群体

1. 受灾群众：报平安短信、语音求助等低速率业务，终端数量最大；
2. 一线救援队伍：灾情图像回传、指挥话音等高优先级业务，对时延与连续性最敏感；
3. 应急指挥部门：需要"最危险的人先接入"的生存优先调度能力与全局态势掌握；
4. 通信保障与应急管理部门：评估卫星直连方案在真实灾害参数下的可行性。

### 1.3 应用环境

场景五要素（同时是仿真建模的输入约束）：

| 要素 | 设定 |
|---|---|
| 网络条件 | 灾后地面公网、核心网、信关站全部瘫痪，终端只能直连卫星 |
| 接入负载 | 海量终端集中、突发发起接入（呼叫风暴） |
| 信道与运动 | LEO 约 7.5 km/s，多普勒大（实测最大约 26 kHz），传播时延 20~50 ms |
| 终端能力 | 终端具备 GNSS 定位，已知卫星星历，可做开环预补偿 |
| 星上约束 | 星上算力、存储有限，机制必须轻量 |

### 1.4 交付形态

项目不接触真实卫星硬件，全部成果以可复现的仿真平台交付：Python 协议级仿真主体、ns-3 离散事件镜像参考实现、指标统计与中文图表报告、双轨交叉验证对照表，以及参数敏感性分析与消融实验数据集。

## 二、需求分析

### 2.1 功能需求

1. 受灾终端在灾害发生后首次接入卫星时只经历最少的手握轮次，以便在信道拥塞前尽快建立链路（对应：协议级两步 RACH 接入）；
2. 切换卫星时通信几乎不中断，以便指挥话音不被打断（对应：认证上下文星间预迁移，先建后断，RACH-less 重连确认）；
3. 最危险区域的终端优先获得接入资源，以便实现"救人优先于报平安"（对应：危险度驱动的生存优先保护信道分级准入）；
4. 星上能够本地验证终端身份并拦截伪造终端，以便在无核心网条件下防止仿冒设备占用接入资源（对应：双根模型 HMAC-SHA256 星上认证 + 假名 + 计数器防重放）；
5. 上报灾情后不必因卫星过顶结束而重新完整接入，以便节省信令与电量（对应：星历驱动的目标星提前锁定 + 一次关键信息比对即确认）；

### 2.2 功能模块划分

按任务卡划分：

| 模块 | 内容 | 技术栈 |
|---|---|---|
| T1 双轨仿真骨架 | Python 轨与 ns-3 轨的目录结构、trace 契约、运行产物隔离 | Python + ns-3 |
| T2 场景与轨道建模 | 真实 TLE 导入、ECEF 星历、可见窗、多普勒、灾害场景参数包 | Python |
| T3 接入握手 | 协议级两步 RACH、Rel-17 四步基线、碰撞退避与拥塞模型 | Python + ns-3 |
| T4 安全认证 | 双根 HMAC-SHA256 凭证、假名、计数器防重放、哈希链续认证 | Python + ns-3 |
| T5~T7 切换 | 星历预测目标星、认证上下文星间预迁移、双条件切换判决、迟滞与冷却、一次比对快速重连 | Python + ns-3 |
| T8 业务连续性 | 指挥话音/灾情图像/报平安短信分级 QoS、业务感知切换提前量 | Python + ns-3 |

| T11 指标评估 | 统一指标计算、多种子置信区间、消融与敏感性扫描、中文图表报告 | Python |

### 2.3 非功能需求

1. 可复现性：任意环境 clone 后可直接运行 Python 轨；随机种子固定，每次运行落独立目录并写 manifest（参数 + git commit + 场景快照），杜绝产物互相覆盖；
2. 可审计性：全部常量按"物理常量 / 标准文献 / 建模假设 / 实测"四类标注来源，溯源表内嵌 HTML 报告；仿真值绝不伪装为实测值；
3. 口径一致性：双轨共用同一指标算法（`eval.compute_metrics` 单一实现）与 16 列 trace 契约，消除口径漂移；
4. 星上轻量化：认证与切换机制满足"不增握手轮次、不显著增信令、计算轻量"三重约束，认证引入的额外时延列为独立指标；
5. 诚实可证伪：核心指标必须随参数扫描单调变化、可出现非零劣化（如星历误差增大时中断上升），不做恒为理想值的同义反复。

### 2.4 技术需求与环境约束

1. 纯仿真验证：仅 ns-3（协议级）与 Python（推演/数据），不依赖真实卫星硬件与真实公网；
2. 无核心网：认证与切换不得假设核心网可用，一切逻辑本地化到卫星载荷；
3. 物理层指纹不进仿真：RF fingerprinting / CSI / SRS 类物理层认证不作为仿真实现模块，仅在威胁分析中作为论证素材；
4. 排除项：区块链共识、跨域 PKI、群组聚合认证、Dolev-Yao 形式化证明均移出主线，归入未来工作。

```
┌─────────────────────────────────────────────────────────────┐
│  接入侧 T3    协议级两步 RACH + 保护信道分级（生存优先）       │
```

## 四、技术选型说明

### 4.1 仿真平台：Python 协议模型 + ns-3 C++ 镜像（双轨交叉验证）

选型：采用双轨架构。

1. Python 轨（`run_sim.py` + `sim/`）：唯一可复现、可审计、评审环境可直接运行的仿真主体，负责协议状态机、轨道与可见性预计算、实验批量驱动、指标统计；
2. ns-3 轨（`.ns3_ref/leo_access.cc`，约 1370 行 C++）：Python 协议模型的镜像参考实现，使用真实 ns-3 离散事件调度器，验证同一协议逻辑在离散事件仿真语义下结论一致。

采用原因：

1. Python 侧可用 skyfield 与 sgp4 精确计算真实 TLE 轨道、可见窗与多普勒，便于多种子批量实验与统计，评审环境零编译门槛；
2. ns-3 侧提供协议级严谨性（真实事件调度、消息收发、竞争退避动力学），避免"纯 Python 推演"被质疑协议失真；
3. 双轨共享同一指标算法与 trace 契约，交叉验证增强可信度；结果口径以 Python 轨为准，ns-3 轨用于一致性佐证。

候选底座调研结论：SNS-3、Hypatia、5G-LENA nr 均经评估（见 `docs/参考资料清单.md`），本项目以"自研轻量 LEO 信道 + 协议状态机"落地，外部 NTN 模块列为可选升级路径（见 `docs/ns3构建说明.md`）。

### 4.2 接入侧：协议级两步 RACH + 保护信道分级

选型：将 Rel-17 四步 RACH 压缩为两步；生存优先调度采用 guard-channel（保护信道）机制，以 Kaufman-Roberts 精确解在线确定高危预留阈值。

采用原因：

1. 两步优于四步已被顶级期刊（IEEE WCL 2025）独立验证；IEEE TWC 论文对 LEO 大时延/大多普勒随机接入做了物理层建模，属背景参照而非"两步 vs 四步"协议对比（定位见 5.2）。本项目在两步基础上叠加星历驱动预补偿、应急突发与轻量认证，属场景化集成创新；
   > **建模边界**：本仿真中「GNSS/星历开环 TA 预补偿」以**免前导竞争 + 两步短握手**体现其收益，**未建模** TA 补偿残差与定时误差（ns-3 侧虽在 `MsgA/2/4` 消息中携带 `taSec` 字段，但该字段不参与定时调整或判定）。详见 `docs/技术决策确认.md` §3.2。
2. 四步基线的附加时延为机理化建模：RAR 响应窗口（160 ms）+ 竞争解决定时器（200 ms）+ 额外几何往返（由斜距实算），不是常量平移，两步/四步对照可证伪；
3. guard-channel 分级用排队论形式化"高危终端独占保护位、med/low 共享且可回收"，比"前导码分组"更贴合代码实际实现，也更能表达"救人优先于报平安"的救灾语义；
4. 保留 Rel-17 四步作为同场景同负载对照基线，使两步增益可量化。

### 4.3 认证侧：双根模型 HMAC-SHA256 + 假名 + 哈希链

选型：双根模型（星座根密钥派生设备根密钥）以 HMAC-SHA256 实例化；假名由 HMAC 派生并在每次切换时轮换；哈希链续认证采用"首联下发种子 + 索引单向递增"。

采用原因：

1. 无核心网约束排除了 5G-AKA 与间接认证（卫星转发、地面验证）；星上轻量化约束排除了全量直接认证与区块链共识。可行设计空间落在"预共享凭证 + 一次性令牌的星上本地比对"，恰是文献（Ad Hoc Networks 2026 间接认证综述）认定的"直接认证兴起"前沿方向；
2. HMAC-SHA256 在 Python 与 C++ 两侧均为真实密码学实现（C++ 侧自实现 FIPS 180-4 SHA-256，非 Mock），认证时延为实测校验耗时（约 0.12 ms），拦截率、漏检率、虚警率三指标可证伪；
3. MAC 截断 4 字节使盲猜漏检概率为 2^-32；计数器单调递增天然防重放；假名与哈希链不增加握手轮次，星上仅需一次哈希比对，满足轻量约束。

**实现状态（★2026-09-22 完整性核查并补齐★）**：
- 双根派生（`dev_key = HMAC(root,"devkey"‖term_id)`）、假名派生（`HMAC(root,"pseudo"‖term_id‖epoch)`）、哈希链（种子 `HMAC(root,"chain"‖term_id)` → 逐跳 `H("CHAIN"‖·)`）、MAC 截断、计数器防重放——**两轨均以真实 HMAC-SHA256 实现**（C++ 侧自实现 FIPS 180-4 SHA-256，非 Mock）。
- **假名轮换（Q2）**：每终端维护假名版本 `epoch`，**每次切换 +1 并重派生信令假名**。Python 侧 `sim/protocol.py`（`term_epoch` / `term_pseudo`，凭证取用当前生效假名）；ns-3 侧 `.ns3_ref/leo_access.cc` 的 `RotateCredential()` 在 `DoHandover` 中调用。核查发现 ns-3 侧该函数**此前仅有定义、全文件无调用（死代码）**，致 ns-3 轨 `假名轮换=0`、与 Python 轨不一致，本次已修复；现两轨均满足「假名轮换次数 = 切换事件数」。
- **哈希链续认证（Q3）**：首联下发种子、切换时逐跳单向推进（天然防重放）；其"一次比对即确认"由**星间预迁移的认证上下文比对**承载——因 §6.2 已选定「星间链路预迁移」为 v1 主通路，续认证语义并入预置上下文的一次比对，未另设独立的链校验消息。此建模边界如实标注，不作超限宣称。

### 4.4 切换侧：星间预迁移（先建后断）+ 失配兜底 + 业务感知

选型：服务星在切换决策时刻把终端认证上下文（假名 + 计数器）经星间链路预迁移到预测目标星，切换时目标星一次比对即确认（RACH-less）；预测失配则回退重新 RACH。

采用原因：

1. 最接近的先例是 3GPP CHO（条件切换）与 RACH-less 切换：它们前移了"准备与同步"，但认证上下文迁移与快速确认仍是空白（标准流程中切换后安全上下文重建依赖核心网，灾区不可用），本项目正是对这一空白的安全维度补全；
2. 星历可预测性是 LEO 场景的确定性先验：真实 TLE 驱动的可见窗计算使"预测下一颗可连卫星"具有物理可复算性；
3. 先建后断使中断定义为 max(0, 新链可用时刻 − 旧链真实丢失时刻)，重叠候选在决策时刻即刻建链，提前量充足时中断趋零、提前量不足或星历误差过大时中断暴露，指标可证伪；
4. 业务感知：指挥话音业务获得额外提前量冗余（voice +12 s、image +4 s、sms 0 s），使不同业务的中断容忍阈值（50/300/2000 ms）分别得到保障。

> **建模边界**：预迁移上下文在本仿真中以 `(term_id → counter)` 明文映射表达（Python `sat_ctx` / ns-3 `g_satCtx`），**未建模**星间签名/加密与"只有目标星能解"的密码学保障，亦未建模新星侧对前星推送内容的独立复核（即星间信任链为**简化假设**）。该简化**不影响指标**（上下文的**值**不参与任何判定，仅以 key 是否存在决定 `has_ctx`），但不宜据此宣称已具备抗星间窃听/伪造的密码学设计。详见 `docs/技术决策确认.md` §3。

### 4.5 轨道与信道：真实 TLE + 链路预算

选型：以 CelesTrak 真实 OneWeb TLE（651 颗）经 SGP4 传播计算 ECEF 星历；信道层建立自由空间链路预算（Eb/N0 → BER → MAC 误码概率），并按 ITU-R 大气斜程模型引入仰角相关衰耗。

采用原因：

1. 真实 TLE 使可见窗、多普勒、斜距具有物理可复算性，而非随机生成；
2. 链路预算让"仰角代价"通过误码率兑现为真实后果（低仰角 → 高 BER → 令牌误码 → 确认失败），避免"仰角无物理后果"的死代码问题；链路参数经重新标定（天底 Eb/N0 约 11.9 dB，25° 掩角边缘约 7.7 dB，叠加衰耗斜率后边缘 BER 显著升高），使模型具备判别力。

## 六、设计取舍决策

### 6.1 密码体制：全量 CL-PKC vs HMAC 双根

决策：保留 HMAC-SHA256 双根模型实例化，完整椭圆曲线无证书密码（EC-Schnorr CL-PKC）列为未来工作。

考虑因素：大创一年周期与协议级仿真定位下，椭圆曲线运算与在轨 KGC 部分私钥下发机制的实现与验证成本高；"无核心网 + 星上本地 + 双根派生"的架构创新用 HMAC 已完整落地，性能结论不受算法替换影响。放弃方案的原因：CL-PKC 的差异化收益（免证书链）在本项目威胁模型（盲伪造 + 密钥泄露两类）下不改变拦截率结论，却显著增加星上算力负担，与轻量化约束相悖。

### 6.2 预迁移通路：星间链路预迁移 vs 终端携带令牌

决策：以星间链路预迁移为 v1 主机制（v1 早期曾定为终端携带令牌，后收敛回预迁移）。

考虑因素：需求原文（Text.txt 第 1 点）即"把认证信息提前打包过去"；预迁移已有硬数据支撑（切换重连总时延 12.02 → 380.92 ms，开启 vs 关闭预迁移，**↓96.8%，约 97%**，见 `docs/双轨交叉验证对照表.md` 第 6 节）；与 PreHO/CHO 类文献对照时是最硬的差异化点。放弃终端携带令牌方案的原因：该方案下目标星仍需校验令牌信封并重建上下文，无法呈现"新星一次比对即确认"的机制优势，且与"提前打包"的原始需求语义不符。

### 6.3 指标口径：预测失配率重定义为预迁移命中率

决策：主指标改为预迁移命中率 = 命中 / (命中 + 失配)，旧"预测失配率"（选中星不等于瞬时仰角最优星）降为参考指标。

考虑因素：旧口径在高密度 LEO 星座的贪婪选星下无判别力（风暴场景接近 1，收口后汶川场景 0.11，语义含混）；"认证上下文是否送对星"才是预测式切换真正要度量的对象。实跑预迁移命中率为 1.0，且关闭预迁移时降为 0.0，指标随机制开关单调响应，可证伪。

### 6.4 物理层指纹认证：不进仿真

决策：RF fingerprinting / CSI / SRS 类物理层认证不作为仿真实现模块，仅在威胁分析中论证"密码层检出上限（拦截率 = 1 − 密钥泄露占比）之外需与物理层特征融合"。

考虑因素：ns-3 物理层为基于模型的抽象，无真实可采信道指纹；项目无硬件与实测数据支撑其性能数字；指纹提取计算重，违背星上轻量化。放弃实现而保留论证，既守住诚信边界，又为敏感性分析中"泄露率-拦截率"线性曲线提供了动机闭环。

### 6.5 空基扩展层：v1 默认关闭

决策：无人机/飞艇中继仅作为可开关配置节点（数量、覆盖半径、驻留时长三项参数）建模，v1 默认关闭，先交付卫星直连基线。

考虑因素：编队控制、轨迹规划与飞行动力学工作量大且非核心；进度紧张时可整体裁剪而不影响接入、认证、切换三条主线交付。代价：计划书"空基增益三配置对比实验"未做，已如实列为成果缺口。

### 6.6 生存优先的吞吐取舍：接受为设计取舍

决策：开启生存优先分级后，聚合接入成功率相对**同负载无优先级口径**下降（核心方案 → 全方案：聚合 **−13.4%**），接受该结果并在正文显式披露。

考虑因素："救人优先"刻意牺牲中低危终端吞吐，是救灾语义的直接体现；同一受控负载下，加入分级调度使 **高危终端成功率 +10.0%**，而中/低危分别 **−19.0% / −19.5%**（核心方案 → 全方案）。负向指标被量化隔离而非隐藏，符合可证伪原则。

> ★2026-09-22 口径更正★：原表述为"全方案对照 Rel-17 聚合 −26.6% ± 3.4"。随四步基线在 T3 容量记账（`RACH_SLOT_UNITS` 四步占 2 单位）与长握手 LOS 越界下变弱，**相对 Rel-17 的聚合成功率现为 +29.0% ± 2.9（正向）**；因此"牺牲中低危"应表述为**同负载下的内部权衡（−13.4%，核心→全方案）**，而非相对基线的下降。原数字已作废。

### 6.7 星历误差建模：引入可扫描漂移使"零中断"可证伪

决策：默认引入 TLE 老化导致的高斯 LOS 预测误差（σ = 5 s），而非使用完美预测。

考虑因素：完美预测下切换中断恒为 0，属于"不可证伪的同义反复"；引入误差后，提前量充足（ho_lead 20 s ≫ 误差 5 s）时中断仍趋近 0，误差超过余量时中断暴露，恰好定量呈现预测式切换的价值边界。

### 7.2 模拟数据与场景设计依据

终端数量、突发强度、危险度分布等为仿真输入（建模假设，非外场实测），设计依据如下：

1. 地理锚点：汶川（31.0083°N, 103.5833°E, 海拔 1326 m，2008 年 8.0 级地震震中区域）与河南（34.75°N, 113.62°E, 海拔 110 m，2021 年特大暴雨区域）；
2. 终端规模 1200/1000：模拟灾区集中突发终端接入的量级，常规场景低于 RACH 容量以验证协议正确性，风暴场景（1 s 内全部涌入、10 ms 时隙容量降为 4）用于放大拥塞效应；
3. 危险度分布 high/med/low = 0.20/0.35/0.45：对应指挥救援、灾情上报、报平安三类人群的典型构成，业务分布 voice/image/sms = 0.20/0.50/0.30 与之正交；
4. 伪造终端占比 5%，其中 15% 持有效泄露密钥（compromised_share）：模拟仿冒设备与密钥泄露两类威胁，使拦截率成为可计算指标（拦截率 ≈ 1 − compromised_share，敏感性扫描已验证该线性关系）；
5. 认证附加时延：由本机 HMAC-SHA256 校验耗时实测（20000 样本）乘以星上抗辐照 CPU 降频系数（1000 倍，可扫描）折算，非硬编码常量。

### 7.3 数据生成方法

1. `sim/data_sources.py` 抓取/缓存 TLE → `sim/orbit.py` 以 SGP4 传播、skyfield 计算逐 15 s ECEF 星历与可见窗；
2. `sim/scenario.py` 参数包生成终端（经纬度、海拔、危险度、业务类型）与突发到达过程（固定随机种子）；
3. `sim/protocol.py` 协议状态机逐事件推进，输出 16 列 trace CSV；
4. `sim/ns3_io.py` 将同一星历与终端表导出为 `ns3_in/`（scenario.json、ephemeris.csv、terminals.csv）供 ns-3 轨消费，回采 trace 后委托同一 `eval.compute_metrics` 统计，保证双轨同参可比。

全部数据均有可访问来源或明确标注为建模假设；仿真值未伪装为实测值；无来源数据一律拒收；每次运行产物目录附 manifest.json（参数、种子、git commit、场景快照）供审计。

### 9.2 三大机制效果分析

1. 两步 RACH：同负载风暴对照下，四步接入时延 652.80 → 两步 193.44 ms，降幅 **70.4%**（P95 1368.46 → 880.13 ms，降 35.7%）。机理归因清晰：省去 RAR 窗口、竞争解决定时器与额外几何往返；**成功率两步 0.705 vs 四步 0.4455（两步高 25.9 pp）**——四步握手更长，在 LEO 高速运动下更易在握手期跨过 LOS 边界而失败（`los_during_handshake` 路径），叠加竞争解决失败在拥塞下放大，共同造成其成功率劣势；两步预补偿握手短、暴露窗口小，与其免竞争特性一致。★2026-09-22 刷新：原"两步略高"表述基于修复前数据，刷新后两步优势显著且结论更强。★
2. 星间预迁移：单变量开关对照下，开启预迁移切换重连总时延 **12.1 ms** vs 关闭 **381.0 ms**，降幅 **96.8%（约 97%）**；预迁移命中率 1.0 → 0.0，指标随机制开关单调响应，结论可证伪。（★2026-09-22 复跑，与旧值 12.02/380.92 一致★）
3. 生存优先分级：风暴场景高危终端接入成功率 **0.9561** 对低危 **0.6362**；加入分级使高危时延 **237.6 → 43.2 ms（↓81.8%）**、高危成功率 **0.8421 → 0.9561**，代价为中/低危分别 **−19.0% / −19.5%**（同负载开关对照）。受控对照下（`--rel17 --reps 3`）高危成功率相对 Rel-17 提升 **+60.6% ± 6.9**，达成并大幅超出计划书"提升 20%"指标（口径为高危终端成功率）。
4. 业务连续性（T8）：压力场景（`t8_stress`，3 种子）指挥话音连续性满足率，业务感知开启 **1.000**（图像 0.954 / 短信 0.897），关闭 **0.806**（图像 0.818 / 短信 0.890），验证分级提前量冗余机制有效。
5. 三阶段消融（3 种子，`--ablation`）：阶段1 两步 RACH 使接入时延 **732.6 → 244.7 ms（↓66.6%）**，并单独带来高危成功率 **+40.9%（0.5857 → 0.8252）**；阶段2 加预测切换与预迁移使切换中断 **916.4 → 0.01 ms（↓约 100%）**、T8 连续性 **+25.6%**；阶段3 加生存优先使高危成功率再 **+10.0%（0.8252 → 0.9395）**。三机制贡献相互独立、边际清晰。

> **关于"预迁移命中率 1.0"**：本协议中，预迁移的目标星与执行切换的目标星由**同一决策**产生（决策选 cand → 上下文推送 cand → 切换执行 cand），协议内不存在"送错星"的失败路径，故开启预迁移时命中率恒为 1.0、关闭时恒为 0.0——该数值是内部一致性结果，并非独立的统计发现。预测式切换真正可证伪、可量化取舍的证据在三处：
> 1. **预测失配率**（选中星 ≠ LOS 时刻瞬时仰角最优星，当前代码 Python 0.126 / 0.107 / 0.085 / 0.096 对 ns-3 0.129 / 0.116 / 0.085 / 0.092，双轨吻合）——量化"提前量下的联合打分 ≠ 即时仰角最优"的取舍代价；
> 2. **敏感性扫描**（ho_lead 2 s → 中断 459.73 ms、20 s → 0.02 ms；ephem_err 5 s → 0.02 ms、30 s → 3267.38 ms，误差超余量时中断非线性陡增）——展示预测式切换的适用边界；
> 3. **预迁移开关对照**（命中率 1.0 ↔ 0.0，切换总时延 12.1 ↔ 381.0 ms，↓96.8%）——指标随机制开关单调响应。

### 9.4 敏感性分析结论

1. 切换提前量 ho_lead：中断随提前量**单调下降**并存在"零中断拐点"（2 s → 459.73 ms、5 s → 157.34、10 s → 14.31、15 s → 0.50、20 s → 0.02、30 s → 0.01 ms），默认 20 s 落在零中断区并留有余量；
2. 星历误差 ephem_err：误差 ≤ 提前量余量时中断趋零，超过后**非线性陡增**（0 s → 0.0、5 s → 0.02、10 s → 33.10、15 s → 365.82、30 s → 3267.38 ms），模型可证伪；
3. 密钥泄露占比 compromised_share：拦截率随泄露占比**单调下降**（0 → 1.000、0.15 → 0.927、0.30 → 0.820、0.50 → 0.531；理论线 1−share = 1.00 / 0.85 / 0.70 / 0.50）。实测略**高于**理论线，系拦截率分母采用「进入认证环节的伪造终端」口径（拥塞未认证者单列，P0-1）在小样本（伪造约 62~71 个）下的采样偏差；趋势与"密码层检出上限"语义成立，为"需与物理层特征融合"提供数据闭环。

三组扫描共同证明：全部指标可证伪、可随参数单调变化，不是恒为理想值的同义反复。

### 9.5 项目价值总结

1. 场景价值：给出灾后无核心网约束下"接入-认证-切换"一体化的可复现仿真方案，2.5 节所列 KPI（三项提升类 + 认证时延 + 拦截率）全部以受控对照与置信区间达标；
2. 方法价值：真实 TLE 驱动 + Python/ns-3 双轨交叉验证 + 统一指标口径 + 常量四类溯源的工程范式，使创新点可证伪、结论可审计；
3. 创新定位：不主张两步 RACH、CHO 等标准机制的协议原创，核心贡献为四点应急场景化组合：无核心网双根星上本地认证架构、认证上下文星间预迁移与预测式切换结合（RACH-less 重连降约 97%）、绑定灾情危险度的生存优先调度、真实 TLE 驱动的可复现突发接入仿真与双轨验证。

### 9.6 局限性与未来改进方向

局限性：

1. ns-3 轨信道为自研轻量 LEO 模型，非 3GPP NTN 物理层模块，保真度有限，指标以 Python 轨为准；
2. 认证根密钥预分发方式与 compromised_share = 0.15 的取值目前为可扫描建模假设，缺文献锚定；
3. 当前链路余量标定下虚警与确认失败率趋零，"仰角代价"在小区边缘的判别力仍需通过降低余量或增大衰耗进一步增强；
4. 空基扩展层三配置增益实验未做（v1 计划内裁剪）；假名"跨域匿名"等更强安全宣称不作为成果。

> 旧版局限"风暴场景双轨绝对值差异（Python 0.439 vs ns-3 0.723）"已于**方案A（双轨同参）**解决：Python 轨改用终端独立位置分布后与 ns-3 同口径，差异收敛至 <1.5%（见 9.3）。

未来方向：接入 CL-PKC 或 EC-Schnorr 完整无证书签名；对接 SNS-3/5G-LENA NTN 模块提升物理层保真度；引入物理层特征与密码层融合的检出上限分析；完成空基增益专项实验。
